# 2026-11-03 음성 변환을 갈아끼울 수 있는 구조로

브랜치 `feat/llm-settings` (커밋 전). 배포 계획의 "Mac 전용 기능 분리" 첫 번째 (`2026-11-03-배포목표와결정사항.md` 1장).

## 요청

"음성 변환(transcriber)을 갈아끼울 수 있는 구조로 바꿔줘. `TRANSCRIBER=local_whisper | (나중에 추가할 다른 방식)` 설정으로 고르게. 지금 동작(로컬 Whisper)은 그대로 기본값. 새 방식은 이번에 구현하지 말고 자리만 만들기."

정한 것: 끄기(`none`)도 이번에 넣는다 — 배포 서버(Whisper 없음)용.

## 구조

```
transcriber.py  (공통 과정 — 그대로)
  ffmpeg로 16kHz 모노 WAV → 조용한 곳에서 구간 나누기(plan.json) → 구간마다 엔진 호출
  → part_NNN.json 저장(이어서 하기) → 2회 재시도 → 합치기 → 원문 JSON·TXT
        │  engine.transcribe(구간 소리, 언어) → [{start, end, text}] (구간 안 시각, 빈 문장 제외)
        ▼
speech_engines.py  (새 파일)
  SpeechEngine  모양: name, loading_stage(준비 중 화면 문구), prepare()(모델 불러오기), transcribe()
  LocalWhisper  지금의 모델 불러오기(CPU, lru_cache) + model.transcribe(옵션 그대로)를 옮김
  ENGINES = {"local_whisper": LocalWhisper}
  DISABLED = "none"
```

- 구간 시각 더하기·반올림(소수 둘째 자리)은 공통 과정에 남겼다. 그래서 어떤 엔진이든 같은 원문 형식이 된다.
- 설정: `TRANSCRIBER: Literal["local_whisper", "none"]`(기본 `local_whisper`). 없는 이름은 설정을 읽을 때 오류(쓸 수 있는 값을 알려 줌) → 서버가 시작하지 않는다.
- `none`:
  - 음성 작업의 `POST /api/jobs/{id}/transcribe` → **503** "이 서버에서는 음성 변환을 하지 않습니다. (TRANSCRIBER=none)". 작업 상태는 바뀌지 않는다.
  - 혹시 처리기까지 가면(예전 대기열 등) 모델을 불러오지 않고 같은 문구로 `FAILED`.
  - 사진(화이트보드) 작업은 그대로 처리 — OCR은 다음 단계에서 따로 고른다.
- `/api/health`에 `transcriber` 추가 (기존 `whisperModel`·`ffmpeg` 유지). 프런트 `Health` 타입에도 추가. 화면은 바꾸지 않았다 — 고를 수 있는 방식이 하나라 '방식 고르기' 메뉴를 만들면 실제 기능 없는 버튼이 되기 때문.

## 새 방식을 붙이는 법 (자리)

1. `speech_engines.py`에 `SpeechEngine` 모양의 클래스(`name`, `loading_stage`, `prepare`, `transcribe`)를 만들고 `ENGINES`에 추가.
2. `core/config.py`의 `transcriber` Literal에 같은 이름 추가 (`tests/test_speech_engines.py::test_config_choices_match_engines`가 둘이 맞는지 본다).
3. 후보: Mac 작업자(서버는 대기열만, Mac이 가져가 변환 — 배포 결정 사항), 외부 음성 인식 API(Groq·OpenAI, 녹음이 외부로 나감).

## 검증 (실제로 한 것)

**먼저 알게 된 것:** 이 작업 전에는 음성 변환 과정을 시험하는 테스트가 없었다 (`test_api.py`는 변환 요청이 202인지, 사진 OCR만). 그래서 "기존 변환 테스트"를 먼저 만들었다.

1. **바꾸기 전 기준값**: Mac 음성 합성(`say`, 한국어)으로 만든 10초 회의 녹음을 지금 코드의 진짜 Whisper small로 변환 (임시 storage, DB 안 씀) → 4문장 정확, 단계 문구 `오디오 준비 중 → Whisper small 모델 불러오는 중 → 구간 1/1 변환 중 → 변환 완료`.
2. **테스트를 바꾸기 전 코드에서 먼저 통과**시킴 (`test_transcriber.py` 5개: 130초를 1분 구간 3개로 나누고 시각 더하기·빈 문장 버리기·옵션 전달·TXT 형식·임시 폴더 정리 / 2구간 실패 → "구간 2/3…" 후 다시 시도하면 2·3구간만 / 1회 실패 후 성공 / 완료 결과 재사용 / 단계 문구). 가짜 모델을 끼우는 곳은 fixture 한 줄.
3. 구조를 바꾼 뒤 **같은 테스트를 fixture의 import 한 줄만 바꿔** 다시 통과.
4. 엔진 고르기 테스트 8개 추가 (config 값과 ENGINES 일치, 기본값, 없는 이름 거부, LocalWhisper 옵션·공백 정리, `none` 503·FAILED·사진은 202·health).
5. 전체 pytest **89개 통과** (76 + 5 + 8). 프런트 `tsc` 통과.
6. **바꾼 뒤 진짜 Whisper small로 같은 녹음 다시 변환 → 원문이 바꾸기 전과 글자 하나까지 같음** (`diff` 차이 없음), 단계 문구도 같음. `TRANSCRIBER=none`으로는 모델을 불러오지 않고 FAILED + 안내 문구.

## 확인하지 못한 것

- 2시간 실제 녹음으로는 다시 돌리지 않았다 (공통 과정 코드는 바꾸지 않았고, 긴 녹음 나누기는 130초·1분 구간 테스트로 확인).
- 지금 켜져 있는 3001 백엔드(start.sh)는 재시작 전이라 새 코드가 아니다. 재시작하면 반영된다.

## 작업 중 발견 (이 단계와 별개)

- `scripts/check-rules.sh`가 **meerkit 생성 프로젝트의 `docker-compose.yml` 변경**을 잡았다. 2026-11-03 10:29에 DB 포트 줄이 `"5432:5432"` → `"5432:5433"`으로 바뀌어 있다 (이 작업에서 고치지 않음). 이 값은 Mac의 5432를 컨테이너 안 5433에 잇는데, 컨테이너 안 Postgres는 5432에서 듣기 때문에 meerkit 자체 명령으로 DB를 켜면 접속이 안 된다. start.sh는 `infra/` 덧씌우기(`ports: !override`)로 포트를 바꾸므로 영향 없음. 되돌릴지는 사용자 결정 대기.
