# 2026-11-02 말모아 자체 로그인 삭제

브랜치 `feat/llm-settings` (커밋 전)

## 요청

"로그인 기능을 npm으로 연결할꺼야. 그러니 로그인 기능을 삭제해줘"

→ 말모아가 직접 만든 로그인(회원가입·로그인 화면·JWT·비밀번호)을 지운다. 어떤 npm 라이브러리를 붙일지는 아직 정하지 않았다.

## 지운 것

| 구분 | 내용 |
|---|---|
| 백엔드 API | `app/api/auth.py` 전체 — `GET /api/auth/status`, `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me` (이제 404) |
| 백엔드 코드 | `core/security.py`의 JWT 발급·검사, 비밀번호 해시(Argon2). `services/accounts.py`의 `adopt_local_user`(첫 가입자에게 로컬 계정 작업 넘기기)·`real_user_count`. 스키마 `UserOut`·`Token`·`Credentials`·`AuthStatus`. 시작할 때의 `JWT_SECRET` 검사 |
| 설정 | `AUTH_ENABLED`, `JWT_SECRET`, `JWT_ALGORITHM`, `JWT_EXPIRE_MINUTES`, `ALLOW_REGISTRATION` (`config.py`·`.env.example`·`.env`) |
| 라이브러리 | `pyjwt`, `pwdlib[argon2]`, `email-validator` (`uv remove`) |
| 프런트 | `/login` 화면(`app/login/`), `login-form.tsx`, 로그인 상태 저장소 `stores/auth.ts`, `lib/api.ts`의 토큰 헤더·401 로그아웃·인증 함수, 타입 `User`·`Token`·`AuthStatus`, 메뉴 막대와 시작 메뉴의 **로그아웃**, 설정 화면의 '로그인' 줄, 도움말의 '로그인 화면이 다시 나와요' |
| 테스트 | 회원가입·로그인·토큰 401·로그인 켜고 끄기·첫 가입자에게 넘기기 테스트 8개 |

## 남긴 것 (일부러)

- **DB `users` 표와 내장 로컬 계정 `local@malmoa.local`.** 작업·일정·참석자·AI 설정이 모두 `user_id`로 계정에 묶여 있어, 표를 지우면 구조를 크게 바꿔야 한다. npm 로그인을 붙이면 "누구의 작업인지"를 다시 이 표에 연결하면 된다. 그래서 **DB 마이그레이션은 하지 않았다.** `password_hash` 칸도 그대로 두었다(로컬 계정은 쓰지 않는 자리 표시 값).
- **사용자별로 걸러 내는 코드**(다른 사용자의 작업·일정은 404). 테스트에서 `X-Test-User` 헤더로 사용자를 바꿔 계속 시험한다(`tests/conftest.py`, 테스트 전용이며 실제 서버에는 없다).
- **`SECRET_KEY`** — 설정 화면에서 넣은 AI 키를 암호화하는 열쇠. 로그인과 상관없다.

## 지금 동작

모든 요청이 로컬 계정으로 처리된다. 화면은 예전 `AUTH_ENABLED=false` 때와 똑같이 바로 열리고, 작업 16개·일정·참석자·Gemini 설정이 그대로 보인다.

## npm 로그인을 붙일 자리

1. **백엔드** `backend/app/core/security.py`의 `get_current_user` — 지금은 로컬 계정을 돌려준다. 라이브러리가 준 토큰·세션을 확인해 `users`의 사용자를 돌려주게 바꾼다. 모든 API가 이 함수 하나를 쓴다.
2. **프런트** `frontend/src/lib/api.ts`의 `send()`와 `createJob()`(업로드, XHR) — 요청에 토큰·쿠키를 실어 보낸다.
3. **프런트** `frontend/src/components/malmoa/app-shell.tsx`의 `AppShell` — 로그인하지 않았으면 로그인 화면으로 보낸다. 로그아웃 메뉴도 여기(`Menu` '파일', 시작 메뉴)에 다시 넣는다.
4. 첫 로그인 사용자에게 로컬 계정의 작업을 넘길지 정한다 (예전 `adopt_local_user`는 git 기록 `c62cd15`에 있다).

## 함께 생긴 문제

- 저장된 AI 키가 `JWT_SECRET`으로 암호화되어 있었다면 다시 입력해야 했다 → 지우기 전에 `SECRET_KEY`만으로 풀리는지 확인함. 트러블 이슈 #28.
- `.env`는 백업 후 고쳤고, 권한이 644(다른 사용자도 읽기 가능)라 600으로 좁혔다.

- 프런트 `tsc`·`eslint` 통과.
- 실제 백엔드 8010 재시작: `/api/health`·`/api/jobs`(16개)·`/api/settings/llm`(Gemini, 문제 없음)·`/api/events`·`/api/people` 200, `/api/auth/status` 404.
- 실제 프런트 3001: `/`·`/jobs`·`/settings`·`/guide` 200, `/login` 404 (주소 응답만 확인. 실제 화면은 자동 녹음 때문에 시험 브라우저로 열지 않음).

## 확인하지 못한 것

- 브라우저에서 메뉴에 로그아웃이 사라진 모습을 직접 보지 않았다 (코드·타입 검사로만 확인).
- 예전에 로그인했던 브라우저에는 `localStorage`의 `malmoa-auth` 값이 남아 있을 수 있다. 이제 읽지 않으므로 해는 없다.

## 추가: 로그인용 DB 칸 삭제 (같은 날)

요청: "만들었던 로그인 관련 DB도 삭제(추후 공동모듈 연결 예정)"

- 마이그레이션 `92823cdd8bd5_drop_users_password_hash` — `users.password_hash` 칸을 지웠다. 로그인 전용으로 남아 있던 DB 항목은 이것 하나였다.
- `users` 표는 **남겼다.** 작업·일정·참석자·AI 설정·AI 사용량이 모두 `user_id`로 이 표에 묶여 있다. 공동 로그인 모듈을 붙이면 그 사용자를 이 표의 행(`id`·`email`)과 연결한다.
- 코드: `User` 모델, `get_local_user`, 테스트 `conftest.py`에서 `password_hash` 제거.
- 검증: `alembic upgrade head` 적용 후 `\d users`에서 칸이 사라진 것 확인, pytest 63개 통과, 백엔드 재시작 뒤 `/api/jobs`(18개)·`/api/people`·`/api/events`·`/api/settings/llm` 200.
- 참고: `.venv/bin/pytest`가 예전 폴더(`Desktop/Malmoa`)의 파이썬을 가리켜 테스트가 모듈을 못 찾았다. `.venv/bin/python -m pytest`로 돌리면 된다 (가상환경을 다시 만들면 고쳐진다).
