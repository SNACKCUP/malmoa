각 기능의 **현재 구현된 동작**을 적었습니다. 파일 경로는 프로젝트 루트 기준입니다.

## F1. 브라우저 직접 녹음

**위치:** `frontend/src/hooks/useRecorder.ts`, `lib/recordingStore.ts`, `components/malmoa/recorder-context.tsx`, `recorder-panel.tsx`

| 항목 | 동작 |
|---|---|
| 녹음 방식 | MediaRecorder, 모노 32kbps(2시간 약 29MB, 2026-11-03 64→32kbps). Chrome은 WebM(Opus), Safari는 MP4/M4A |
| 자동 저장 | 10초(`CHUNK_INTERVAL_MS`)마다 조각을 브라우저 IndexedDB에 저장 |
| 복구 | 녹음 중 탭이 닫혀도 다시 열면 "이전 녹음 불러오기"로 저장된 조각을 이어 붙여 복구 |
| 조작 | 시작 · 일시정지 · 재개 · 종료. 종료 후 재생 · 다시 녹음 · 저장하기(다운로드) · 텍스트로 변환 |
| 회의실 모드 | 기본 켬. 켜면 `echoCancellation`·`noiseSuppression` 끔(멀리 있는 화자 소리를 깎지 않도록), `autoGainControl` 켬 |
| 설정 기억 | 마이크 장치·회의실 모드는 Zustand `useRecorderPrefs`(localStorage `malmoa-recorder`) |
| 보조 기능 | 입력 레벨 표시, 일정 시간 소리가 작으면 경고, Wake Lock으로 화면 꺼짐 방지 |
| 화면 이동 | 녹음기는 `RecorderProvider`로 앱 틀(AppShell)에 있음 → 결과 보기·작업 목록으로 가도 녹음 유지. 홈이 아닌 화면에는 상단 **녹음 막대**(`RecordingDock`, `aria-label="녹음 상태"`) 표시 |
| 로그인이 풀려도 (2026-11-03) | 녹음기를 쓰는 중(녹음·일시정지·정리 중·보내지 않은 녹음)에 로그인이 풀리면(토큰 갱신 실패·인터넷 끊김·로그인 만료) 화면을 로그인 창으로 **바꾸지 않고** 바탕화면 위에 로그인 창을 띄운다(`SessionLostOverlay`). 녹음은 계속되고 "로그인이 풀렸습니다. 녹음은 계속되고 있습니다 (시간)… 이 탭을 닫지 마세요." 안내와 **녹음 끝내기** 단추. 20초마다 로그인 서버에 다시 물어 돌아오면 저절로 다시 로그인. 보내기는 로그인 뒤 |
| 오류 종류 | `unsupported`·`insecure`(http)·`denied`·`notfound`·`busy`·`device-lost`·`storage`·`unknown` 각각 한국어 안내 |

마이크는 **보안 연결(https 또는 localhost)** 에서만 동작합니다. 다른 노트북은 시안 서버의 `https://…:5443`을 씁니다.

## F2. 파일 업로드 (음성·사진)

> 2026-11-03 통합 단계 5-2: 저장소가 R2(s3)면 브라우저가 서명 주소로 **저장소에 바로** 올리고(화면 서버·백엔드를 거치지 않음) 끝났다고 알리면 작업이 생긴다. 로컬 저장소면 예전처럼 백엔드로 올린다 — 화면이 서버 답(409 `DIRECT_UPLOAD_OFF`)을 보고 저절로 고른다(`lib/malmoa/api.ts` `createJob`). 녹음기·업로드·화이트보드 사진 모두 같다.

**위치:** `frontend/src/components/malmoa/upload-panel.tsx`, `backend/app/api/jobs.py` `create_job`

**저장 위치 (2026-11-03):** 원본·변환 원문·회의록은 `STORAGE_BACKEND` 저장소 — `local`(기본, `backend/storage/uploads·transcripts·minutes/`) 또는 `s3`(비공개 버킷 하나, 키 `uploads/<작업ID>.<확장자>`·`transcripts/<작업ID>.json|.txt`·`minutes/<작업ID>.md|.json`, 공개 주소 없음 — 파일은 로그인 확인 후 백엔드가 전달). 업로드는 `work/incoming/`에 크기 제한을 보며 받은 뒤 저장소로 옮긴다(S3는 16MB 단위 분할 업로드). 변환 임시 파일 `work/`는 항상 로컬. 아래의 `storage/…` 경로는 local 모드 기준. `docs/2026-11-03-저장소분리.md`

| 항목 | 내용 |
|---|---|
| 음성 형식 | `.mp3 .wav .m4a .webm .mp4 .ogg` |
| 사진 형식 | `.jpg .jpeg .png .heic .heif .webp` → 자동으로 `source="image"` |
| 용량 제한 | `MAX_UPLOAD_MB`(기본 500MB). 1MB씩 받으며 초과 즉시 중단·삭제 → 413 |
| 표시 | 파일 이름·크기, 업로드 진행률(XHR progress) |
| 버튼 | 음성: "업로드하고 텍스트로 변환" / 사진: "올리고 글자 읽기". "화이트보드 사진 찍기 · 올리기"는 `capture="environment"`(휴대폰이면 카메라 바로 열림) |
| 보안 | 저장 파일 이름은 `{job_id}{확장자}`로 새로 만듦. 원래 이름은 경로 문자를 제거해 표시용으로만 사용(최대 200자) |
| 오류 | 지원하지 않는 형식(400), 빈 파일(400), 용량 초과(413) |

업로드 직후 프런트가 `POST /transcribe`를 바로 호출합니다(`uploadAndTranscribe`).

## F3. 음성 → 텍스트 (Whisper)

**위치:** `backend/app/services/transcriber.py`(긴 녹음 처리 과정, 엔진과 무관) + `speech_engines.py`(구간 하나를 문장으로 바꾸는 엔진, 2026-11-03)

**방식 고르기:** `TRANSCRIBER` — `local_whisper`(기본, 이 컴퓨터에서 Whisper) / `none`(이 서버는 음성 변환 안 함: 변환 요청은 503 "이 서버에서는 음성 변환을 하지 않습니다. (TRANSCRIBER=none)", 사진 글자 읽기는 그대로). 새 방식(Mac 작업자·외부 API 등)은 엔진 클래스 + 설정 이름 하나로 붙인다 — `docs/2026-11-03-음성변환-교체구조.md`

1. ffmpeg로 원본을 16kHz 모노 WAV로 변환 (`storage/work/{id}/audio.wav`). 시스템 ffmpeg가 없으면 `imageio-ffmpeg` 내장 실행 파일
2. `SEGMENT_MINUTES`(기본 5분)마다 구간을 나누되, **목표 지점 앞 20초 중 가장 조용한 0.1초**에서 자름 → 경계를 `plan.json`에 저장(재개 때 같은 경계 사용)
3. 구간마다 엔진 실행. 로컬 Whisper: `language=ko`, `fp16=False`, `condition_on_previous_text=False`(반복 출력 방지), CPU 사용(MPS는 오류가 잦음)
4. 구간 결과를 `part_NNN.json`으로 즉시 저장. 구간당 2회 시도
5. 모두 끝나면 `storage/transcripts/{id}.json`(세그먼트)·`.txt`(`[시:분:초] 문장`)로 합치고 임시 폴더 삭제
6. 이미 결과 파일이 있으면 다시 변환하지 않고 재사용

**모델:** `WHISPER_MODEL`(기본 `small`). 정확도 한계가 확인됨 → [05-작업규칙.md](05-작업규칙.md)의 "알려진 문제" 참고.

## F4. 사진 → 텍스트 (화이트보드)

**위치:** `backend/app/services/ocr.py`, `transcriber.py` `_read_image`

- macOS Apple Vision(`pyobjc-framework-Vision`), 인식 언어 `ko-KR`, `en-US`, EXIF 방향 반영
- 줄을 위→아래, 왼→오른 순서로 정렬
- 결과는 음성 원문과 **같은 형식**으로 저장: 세그먼트 `{start:0, end:0, text, confidence}`. TXT에는 시간 표시 없음
- 확신도 0.4(`LOW_CONFIDENCE`) 미만 줄은 화면에서 `확인 필요` 배지
- 상태 문구: "글자 읽기 대기" → "사진에서 글자 읽는 중" → "글자 읽기 완료"
- Mac 전용 기능(Vision). 다른 OS 서버에서는 동작하지 않음

## F5. 작업 상태 관리

**위치:** `backend/app/db/models.py`, `core/storage.py`, `services/worker.py`, `main.py`

| 상태 | 의미 |
|---|---|
| `QUEUED` | 대기 (업로드 직후, 또는 순서 대기 중이면 `progress=0`) |
| `TRANSCRIBING` | 음성 변환 또는 사진 글자 읽기 중 |
| `SUMMARIZING` | 회의록 작성 중 |
| `COMPLETED` | 마지막 요청한 단계 완료 (변환 완료이든 회의록 완료이든) |
| `FAILED` | 실패. `errorMessage`에 한국어 사유와 재시도 안내 |

- 작업 ID는 `moa-` + UUID (2026-11-02, 예전 작업도 모두 바꿈: 마이그레이션 `837bbda71524`). 상태·진행률(`progress` 0–100)·단계 문구(`stage`)는 PostgreSQL `jobs` 테이블
- 처리 단계는 상태가 아니라 `transcriptReady`·`minutesReady` 플래그로 판단
- **대기열은 DB**(2026-11-03, `jobs.task`·`claimed_by`·`heartbeat_at`, 서버 메모리에 두지 않음). 작업자는 한 번에 한 작업(Whisper가 CPU·메모리를 많이 씀), 서버가 여러 대여도 같은 작업을 둘이 가져가지 않음(`FOR UPDATE SKIP LOCKED`). 같은 작업 중복 요청은 409
- 작업자 역할 `WORKER_TASKS`(배포 서버 `["minutes"]`, Mac 작업자 `["transcribe"]`)
- 서버가 꺼지거나 재시작해 생존 신호가 3분 넘게 끊긴 작업은 자동으로 다시 대기열("…중단되어 다시 순서를 기다리는 중") → 완료 구간부터 이어서. 3번 끊기면 `FAILED`("작업 중 서버가 여러 번 멈춰…"). 다른 서버가 재시작해도 처리 중인 작업은 그대로
- 회의록 구간 메모는 저장소 `minutes/{id}.notes/`(서버 디스크에 남기지 않음)
- 프런트는 처리 중인 작업이 있을 때만 2초마다 폴링(TanStack Query `refetchInterval`)

## F6. AI 회의록 작성

**위치:** `backend/app/services/minutes.py`, `chunker.py`, `llm.py`(제공자별 호출·키 암호화)

- 조건: 원문 있음, 작업 주인의 AI 연결이 완성됨(설정 화면 저장값 → 없으면 `.env`). 없으면 400과 "설정 화면의 'AI 회의록 연결'에서…" 안내
- 제공자(2026-11-02): **OpenAI · Anthropic(Claude) · Google Gemini · OpenAI 호환(직접 주소, Ollama 등)**. Claude만 전용 SDK, 나머지는 OpenAI SDK. 응답의 ```json 블록·앞뒤 설명은 걸러서 JSON만 읽음
- 원문 분할: Whisper 문장 경계에서만 자르며 각 줄에 `[시:분:초]` 표시. 구간당 최대 `MINUTES_CHUNK_CHARS`(12,000자)
- 한 구간이면 API 1회. 길면 **구간별 메모(map) → 통합 회의록(reduce)**. 구간 메모는 `storage/work/{id}_minutes/chunk_NNN.json`에 저장·재개
- 응답은 JSON으로 받아 Pydantic 검증(실패 시 재요청 2회). 비어 있는 담당자·기한은 자동으로 `확인 필요`
- 결과: `storage/minutes/{id}.md`(본문), `{id}.json`(생성 시각·모델·수정 시각 등). 사용 토큰은 `jobs.llm_tokens`에 누적(실패해도 기록)
- 이미 회의록이 있으면 409 → `?force=true`로 새로 만들기
- `OPENAI_BASE_URL`로 OpenAI 호환 서비스 사용 가능 (화면 설정이 없을 때)
- 2026-11-02 OpenAI 키 연결(`gpt-5.4-mini`), **계정 크레딧 0이라 실제 호출은 아직 실패(429)** → 충전 전까지는 F8 복사 방식
