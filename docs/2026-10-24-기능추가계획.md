# 말모아 기능 추가 계획 — 녹음 중 결과 보기·화이트보드 사진·텍스트 복사

Oct 24, 2026 · @onepo

## 요약

세 가지 요청을 모두 이 Mac의 말모아 앱(http://localhost:5173)에 넣는 계획입니다. 이 문서를 확인하고 승인하시면 그때 코드를 고칩니다.

| 요청 | 지금 문제 | 바꿀 방향 |
| --- | --- | --- |
| 1. 녹음하면서 결과 보기 | 결과 보기를 누르면 홈 화면이 닫히면서 녹음이 멈춤 | 녹음기를 화면 전체의 바탕에 두어, 다른 화면으로 가도 녹음이 계속되게 함. 화면 아래에 작은 녹음 막대 표시 |
| 2. 화이트보드 사진 → 텍스트 | 사진을 올리는 기능이 없음 | 사진을 올리면 이 Mac 안에서 글자를 읽어 텍스트로 바꿈. 음성 녹음과 같은 목록·결과 화면에서 확인 |
| 3. 텍스트 그대로 복사 | 그냥 복사 버튼(‘원문만 복사’)은 있지만 작고 떨어져 있어 찾기 어려움 | ‘회의록 요청문과 함께 복사’ 바로 옆에 같은 크기로 ‘텍스트만 복사’를 둠 |

## 1. 녹음하면서 결과 보기

**원인:** 녹음기가 홈 화면의 ‘직접 녹음’ 칸 안에만 들어 있습니다. 결과 보기를 누르면 홈 화면이 닫히고, 그때 녹음기도 함께 꺼져 녹음이 멈춥니다. 그때까지 녹음한 것은 10초 단위로 브라우저에 남아 ‘불러오기’로 되살릴 수 있지만, 그 뒤는 녹음되지 않습니다.

**바꿀 방법:** 녹음기를 홈 화면이 아니라 말모아 전체 화면의 바탕(사이드바가 있는 틀)으로 옮깁니다. 그러면 결과 보기, 작업 목록, 사용 안내, 설정 어느 화면으로 가도 녹음이 계속됩니다.

**화면 변화:** 홈이 아닌 화면에서 녹음 중이면 오른쪽 아래에 작은 녹음 막대가 떠 있습니다.

```text
┌─────────────────────────────────────────────┐
│ ● 녹음 중  00:42:17   [일시정지] [녹음 화면으로] │
└────────────────────────────────────────────┘
```

- ‘녹음 화면으로’를 누르면 홈으로 돌아와 종료·텍스트로 변환을 합니다.
- 막대에서 일시정지·재개도 됩니다. 종료는 실수로 누르지 않도록 홈 화면에서만 합니다.
- 녹음 중 결과 보기로 이전 회의의 원문을 보고, 복사하고, 다시 돌아와도 녹음은 그대로 이어집니다.

**남는 제한:** 브라우저 탭을 닫거나 새로고침하면 녹음은 여전히 멈춥니다(닫기 전에 경고가 나오고, 그때까지의 녹음은 불러오기로 복구됨). 결과를 새 탭으로 여는 것은 괜찮습니다.

참고: 다른 노트북용 화면(시안, 5300·5443)은 결과 보기가 창 위에 뜨는 방식이라 이미 녹음이 끊기지 않습니다.

## 2. 화이트보드 사진 → 텍스트

**방법:** 사진을 올리면 macOS에 들어 있는 글자 인식 기능(Apple Vision)으로 이 Mac 안에서 글자를 읽습니다. 사진은 외부로 보내지 않고, 비용도 들지 않습니다. 이 Mac(macOS 26.5)에서 한국어 인식을 지원하는 것을 확인했습니다.

**올리는 곳:** 홈 화면의 ‘파일 업로드’에 **‘화이트보드 사진’** 버튼을 추가합니다. 녹음 중에도 바로 올릴 수 있고, 휴대폰 브라우저에서 열면 카메라가 바로 켜집니다. 지원 형식: JPG · PNG · HEIC(아이폰 사진) · WEBP.

**결과:** 사진 하나가 ‘최근 작업’에 하나의 항목으로 나타나고(사진 아이콘), 결과 보기에서 원본 사진과 읽어 낸 텍스트를 나란히 봅니다. 텍스트 복사·TXT 다운로드·회의록 요청문 복사는 음성과 똑같이 됩니다.

**미리 시험한 결과:** 손글씨 글꼴로 만든 화이트보드 그림(1200×800)을 읽혔습니다. 0.8초 걸렸습니다.

| 사진의 글 | 읽어 낸 글 |
| --- | --- |
| 1. 로그인 · 회원가입 → 10월 말 | 1. 로그인 • 회원가입 -> 10월 말 |
| 2. 관리자 화면 → 11월 첫째 주 | 2. 관리자 화면 -> 11월 첫째 주 |
| 3. 매무새 기능정의서 자동 생성 | 3. 매무새 기능정의서 자동 생성 |
| API 키 발급 / 비용 확인!! | API 키 발급 / 비용 확인!! |
| 미어킷 출시 일정 (다른 글과 겹쳐 쓴 제목) | 당되어킷절사활정 (실패) |

**한계:**

- 또박또박 쓴 줄은 잘 읽지만, **글자가 겹치거나 흘려 쓴 글, 기울어진 글**은 틀리거나 빠집니다.
- 도형·화살표·그림의 의미는 읽지 못합니다. 글자만 읽습니다. (화살표 → ‘->’ 정도는 됨)
- 인식 확신이 낮은 줄은 색으로 표시해 확인하기 쉽게 합니다.
- 실제 화이트보드 사진(빛 반사, 비스듬히 찍은 사진)으로는 아직 시험하지 않았습니다. 만든 뒤 실제 사진 한두 장으로 확인이 필요합니다.
- 손글씨가 알아보기 어려운 경우 AI(사진을 이해하는 모델)로 읽는 방법이 더 정확하지만, 사진이 외부로 나가고 API 키가 필요해 이번 범위에서는 뺍니다.

## 3. 텍스트 그대로 복사

**지금:** 결과 보기 › 변환 원문에서 파란 상자 안에는 ‘회의록 요청문과 함께 복사’만 크게 있고, 요청문 없는 ‘원문만 복사’는 아래쪽 오른편에 작게 떨어져 있어 눈에 띄지 않습니다. 멘토링·강의 등 회의록이 아닌 용도로 쓸 때는 요청문 없이 텍스트만 필요합니다.

**바꿀 화면:** 파란 상자를 ‘복사하기’ 상자로 바꾸고, 세 버튼을 나란히 둡니다.

```text
복사하기
[ 텍스트만 복사 ]  [ 시간 포함 복사 ]  [ 회의록 요청문과 함께 복사 ]
  멘토링·기타 용도      다시 들을 위치가       ChatGPT·Claude에 붙여
  그대로 사용         필요할 때 [00:12:34] …      회의록 만들 때
```

| 버튼 | 복사되는 내용 |
| --- | --- |
| 텍스트만 복사 | 문장만 줄바꿈으로 이어진 텍스트 (요청문·시간 없음) |
| 시간 포함 복사 | 각 줄 앞에 \[시:분:초\] (TXT 다운로드와 같은 형식) |
| 회의록 요청문과 함께 복사 | 지금과 같음 (회의록 형식·‘확인 필요’ 규칙 + 시간 포함 원문) |

화이트보드 사진의 결과에는 시간이 없으므로 ‘시간 포함 복사’는 보이지 않습니다. 다른 노트북용 화면(시안)의 결과 창에도 같은 세 버튼을 넣습니다.

## 작업 범위와 순서

승인하시면 작고 위험이 적은 것부터 3 → 1 → 2 순서로 만들고, 하나씩 시험한 뒤 다음으로 넘어갑니다. DB 테이블 변경은 없습니다.

| 순서 | 작업 | 고칠 곳 | 시험 |
| --- | --- | --- | --- |
| 1 | 텍스트 복사 버튼 3개 | 화면: 결과 보기(job-result), 시안 결과 창 | 버튼별 클립보드 내용 확인 |
| 2 | 녹음하면서 결과 보기 | 화면: 녹음기를 앱 틀(app-shell)로 옮김, 녹음 막대 새로 만듦 | 녹음 중 결과 보기·작업 목록을 오가고 녹음 시간이 계속 늘어나는지, 끝난 뒤 파일이 끊김 없이 변환되는지 |
| 3 | 화이트보드 사진 | 서버: 사진 형식 받기, 글자 읽기(Apple Vision), 사진 보기 API. 화면: 사진 올리기 버튼, 결과에 사진·텍스트 표시 | 자동 테스트 + 실제 화이트보드 사진 |

추가되는 설치물: 서버에서 Apple Vision을 부르는 Python 패키지 하나(pyobjc-framework-Vision). 다른 외부 서비스나 유료 API는 없습니다.

## 진행 결과 (10월 24일)

세 가지 모두 만들어 이 Mac의 말모아 앱(5173)과 다른 노트북용 화면(시안 5300·5443)에 반영했습니다. 실제 데이터와 섞이지 않게 별도 테스트 서버·DB에서 브라우저로 직접 눌러 확인했습니다.

| 기능 | 확인한 것 | 결과 |
| --- | --- | --- |
| 1. 녹음하면서 결과 보기 | 녹음 시작 → 결과 보기로 이동 → 작업 목록 → 다른 결과 → 녹음 화면으로 → 종료 | 녹음 막대 시간이 4초 → 7초로 계속 흐르고, 홈에서 11초 녹음이 끊김 없이 종료됨 |
| 2. 화이트보드 사진 | 사진 올리기 → 글자 읽기 → 결과 보기 | 사진 표시, 5줄 읽음, 확신 낮은 1줄에 ‘확인 필요’ 표시. 서버 자동 테스트 1개 추가(전체 13개 통과) |
| 3. 복사 버튼 3개 | 버튼마다 클립보드 내용 확인 | 텍스트만 / [00:00:00] 시간 포함 / 회의록 요청문(사진이면 ‘화이트보드 사진에서 읽은 내용’ 문구) 모두 정상 |

- 브라우저 콘솔 오류 0개, 타입 검사·코드 검사·빌드 통과.
- 서버(백엔드)만 다시 시작했고, 화면 서버는 그대로 두어 열려 있던 페이지는 새로고침되지 않았습니다.
- 추가 설치: pyobjc-framework-Vision (Apple Vision 호출용, 외부 전송 없음).

**아직 확인하지 못한 것:** 실제 화이트보드 사진(빛 반사·비스듬한 각도), 휴대폰 카메라로 바로 찍어 올리기, 실제 마이크로 녹음 중 화면 이동. 처음 쓸 때 한 번씩 확인해 주세요.

**사용 방법 요약**

1. 녹음 중 다른 회의 결과를 보려면 그냥 결과 보기를 누릅니다. 오른쪽 아래 녹음 막대로 일시정지하거나 ‘녹음 화면으로’ 돌아옵니다.
2. 화이트보드는 홈의 파일 업로드에서 **화이트보드 사진 찍기 · 올리기** → **올리고 글자 읽기**. 최근 작업에 사진 아이콘으로 나타납니다.
3. 결과 보기의 **복사하기** 상자에서 용도에 맞는 버튼을 누릅니다.
