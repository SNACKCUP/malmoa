# 2026-11-02 AI 사용량 기록·한도·경고

브랜치 `feat/llm-settings` (커밋 전)

## 요청

"API 전체 사용량 중 얼마를 사용했는지 표시할 수 있어?" → 제안한 4가지 중 **1~3번**을 만든다.

1. AI 사용 기록 남기기 (작업을 지워도 남게)
2. 설정 화면에 'AI 사용량' 칸 (오늘·이번 달·전체)
3. 사용자가 넣은 한도와 비교해 % 막대, 80% 넘으면 경고

(4번 예상 비용은 하지 않음)

## 왜 "제공자의 남은 양"이 아닌가

- Gemini: 무료 등급 한도는 Google AI Studio 화면에서만 보이고, 남은 양을 알려 주는 API가 없다.
- OpenAI·Claude: 사용량·비용 API가 있지만 **관리자(Admin) 키**가 필요하다. 권한이 넓어 개인용 로컬 앱에 넣지 않기로 했다.
- 그래서 **말모아가 직접 쓴 양을 세고**, 사용자가 넣은 한도와 비교한다. 같은 키를 말모아 밖에서도 쓰면 그 양은 들어가지 않는다(화면에 안내).

## 기록 (`llm_usage`)

- `services/minutes.py`의 `_ask()`가 AI 응답을 받을 때마다 `Usage.on_call` → `ai_usage.record()`로 한 줄을 남긴다.
  - 한 줄 = 시각, 사용자, 작업 ID, 파일 이름, 제공자, 모델, 호출 1, 입력·출력 토큰.
  - 형식이 틀려 다시 물은 호출, 나중에 실패한 회의록의 앞 구간 호출도 들어간다(실제로 토큰을 썼으므로).
  - 제공자가 거절한 호출(키 틀림·크레딧 부족 등 `LlmError`)은 토큰 정보가 없어 기록하지 않는다.
  - 기록이 실패해도 회의록 작성은 멈추지 않는다(로그만 남김).
- 작업을 지우면 `job_id`만 NULL이 되고 줄은 남는다(FK `ON DELETE SET NULL`). 파일 이름은 따로 복사해 두어 화면에 `[지운 작업] 회의.m4a`로 보인다.
- 사용자를 지우면 같이 지워진다(`ON DELETE CASCADE`).
- 기존 `jobs.llm_tokens`(작업별 합계)는 그대로 둔다.

## 한도 (`llm_usage_limits`)

- 사용자마다 한 줄: `monthly_tokens`(한 달 토큰), `daily_calls`(하루 호출). 둘 다 선택, 비우면 한도 없음.
- 입력 범위: 1 ~ 20억 토큰, 1 ~ 100만 번 (그 밖은 422). 화면은 쉼표·공백을 지우고 읽는다.
- 한도를 넘어도 회의록 만들기를 **막지 않는다**. 직접 넣은 기준이라 실제 제공자 한도와 다를 수 있어서다.

## 하루·한 달 기준

한국 시간 자정과 매달 1일 0시(`Asia/Seoul`). 응답의 `monthStart`·`nextDay`로 화면에 "언제 0부터 다시 세는지"를 보여 준다.
(Gemini 무료 등급의 하루 한도는 Google 쪽 기준 시각에 초기화되므로 말모아의 '오늘'과 몇 시간 어긋날 수 있다.)

## API

- `GET /api/usage` → 오늘·이번 달·전체 합계, 이번 달 모델별, 최근 20개, 한도
- `PUT /api/usage/limits` `{monthlyTokens, dailyCalls}` → 같은 응답

자세한 형식은 `04-API명세.md` 'AI 사용량'.

## 화면

- **설정 › AI 사용량** (`#usage`, `usage-card.tsx`): 오늘·이번 달·전체 칸(토큰, 입력·출력, 호출 수) → 한도 막대(이번 달 토큰, 오늘 호출) → 한도 입력·저장 → 이번 달 모델별 표 → 최근 기록(접힘, 회의 이름을 누르면 뷰어).
- 한도의 **80% 이상**: 막대가 빨개지고 `80% 넘음` 표시와 경고문. **100% 이상**: `한도 넘음`과 "AI 프롬프트 포함 복사로 ChatGPT·Claude에서 만드는 방법" 안내.
- **회의록 뷰어**의 'AI 회의록 만들기' 안내에도 80% 이상이면 "정해 둔 AI 사용 한도에 가깝습니다 · 이번 달 토큰 86% 사용 · AI 사용량 보기"를 띄운다(AI를 부르기 직전에 보이도록).
