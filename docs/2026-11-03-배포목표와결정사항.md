### meerkit 연결 시 문제점 (형태별)

**① 쿠키·도메인**

meerkit 리프레시 토큰은 httpOnly 쿠키 `meerkit_refresh`(경로 `/api/auth`, `SameSite=Lax`, 14일)이다. 브라우저 입장에서 **화면을 연 주소와 같은 출처의 `/api/auth`**로 가야 쿠키가 저장되고 실린다. 그래서 meerkit 백엔드를 브라우저가 직접 부르지 않고, 말모아 프런트(Next.js)가 `/api/*`를 meerkit 백엔드로 넘기는(rewrites) 구조가 전제다.

| 형태 | 문제 |
|---|---|
| A | 터널 주소(HTTPS) 하나로 들어오면 그대로 동작. 배포에서는 `COOKIE_SECURE=true` 필요. 터널 없이 `http://`로 열면 쿠키·마이크가 안 됨 |
| B | 말모아 프런트(Mac)가 `/api/*`를 Render의 meerkit으로 넘김. 쿠키는 말모아 주소로 저장되므로 동작. 로그인·토큰 갱신 요청마다 Mac→Render를 거침 |
| C | Vercel의 rewrites가 Render의 meerkit으로 넘김. 쿠키는 Vercel 쪽 말모아 도메인에 저장. 사용자 도메인을 붙이면 그 도메인 기준 |

공통: meerkit `.env`의 `FRONTEND_BASE_URL`(메일 링크), `SOCIAL_REDIRECT_BASE_URL`(구글 로그인), `CORS_ORIGINS`를 **말모아 프런트 주소**로 맞춰야 한다. meerkit 코드는 고치지 않고 설정으로만 맞춘다.

**② `/api` 배분**

- 브라우저의 `/api/*`는 전부 meerkit 몫이다. 말모아 프런트에 Next.js `app/api/` 경로를 만들면 안 된다 (rewrites와 충돌).
- 말모아 백엔드도 경로가 `/api/jobs`처럼 `/api`로 시작한다. 하지만 **다른 주소**(`NEXT_PUBLIC_API_URL`, 예: `https://api.말모아도메인`)로 직접 부르므로 겹치지 않는다. 말모아 백엔드를 rewrites로 넘기지 않는 것이 규칙.
- 500MB 업로드는 지금처럼 프런트 서버를 거치지 않고 말모아 백엔드로 바로 보낸다 (Vercel을 거치면 요청 크기 제한에 걸릴 수 있음).
- C에서는 말모아 백엔드가 다른 출처이므로 CORS에 말모아 프런트 주소를 넣어야 한다. 쿠키를 쓰지 않고 `Bearer` 헤더만 쓰므로 쿠키 문제는 없다.

**③ 비밀키 공유**

- 액세스 토큰은 HS256(대칭키)이다. 말모아 백엔드가 검증하려면 meerkit과 **같은 `JWT_SECRET_KEY`**를 가져야 한다.
- 위험: 이 키를 가진 쪽은 **토큰을 만들 수도 있다.** 말모아 서버가 뚫리면 meerkit의 어떤 회원(관리자 포함)으로도 토큰을 위조할 수 있다. meerkit을 여러 서비스가 함께 쓰면 위험이 서비스 수만큼 커진다.
- 대응:
  - 키는 각 PaaS의 비밀 설정에만 둔다 (코드·문서·Mac 작업자에는 두지 않음).
  - 키를 바꾸면 모든 사용자가 다시 로그인해야 한다는 점을 운영 절차에 적는다.
  - Mac 작업자는 이 키 대신 작업자 전용 열쇠(`WORKER_TOKEN`)만 쓴다.
  - 근본 해결(공개키 방식 RS256, 또는 말모아가 meerkit에 토큰을 물어보는 방식)은 meerkit 쪽 변경이나 요청당 추가 호출이 필요하다. 팀 규모에서는 공유키로 시작하고 기록만 남긴다.
- A·B·C 모두 해당한다. A는 키가 Mac 한 곳에만 있어 노출 면은 가장 작다.

**④ 탈퇴 동기화**

meerkit에서 확인한 동작:
- 탈퇴하면 `deactivated_at`가 찍힌다.
- 보관 기간(`ACCOUNT_RETENTION_DAYS`, 기본 365일)이 지나면 매일 배치(`account-purge.yml`)가 개인정보를 지운다.
- **다른 서비스에 알려 주는 기능(웹훅·이벤트)은 없다.**

그래서 생기는 문제:
- 말모아는 토큰 서명만 확인하므로, 탈퇴·정지 직후에도 이미 받은 액세스 토큰은 **최대 30분** 더 통한다. 그 뒤에는 토큰 갱신이 meerkit에서 거부되어 접속할 수 없다.
- 말모아에 남은 그 사람의 **녹음·원문·회의록은 자동으로 지워지지 않는다.**

| 방법 | 장단점 |
|---|---|
| 관리자가 말모아에서 직접 삭제 | 팀 규모에 충분, 구현 작음. 사람이 잊을 수 있음 |
| 말모아 배치가 meerkit 관리자 API로 탈퇴 회원을 조회해 정리 | 자동. 관리자 권한 토큰(서비스 계정)을 말모아에 둬야 함 |
| 말모아가 meerkit DB를 읽기 전용으로 조회 | 자동. 두 DB가 묶임 (분리 원칙과 어긋남) |
| 요청마다 meerkit `/api/users/me`로 확인 | 탈퇴 즉시 차단. 요청마다 호출이 하나 늘어남 |

팀 규모에서는 "관리자 직접 삭제"로 시작하고, 외부 공개 때 "배치 정리"를 붙이는 것을 추천한다. 탈퇴 후 말모아 데이터를 언제 지울지(즉시, meerkit과 같은 365일, 기타)는 3장에서 정한다.

### 추천 형태

**C + Mac 작업자.**
- 팀원이 언제든 접속할 수 있고, Mac이 꺼져도 변환만 기다린다.
- 녹음·사진은 외부 회사로 보내지 않는다. Mac 작업자로 내려오고, 저장은 우리 저장소에 한다.
- 나중에 외부 공개로 넓힐 때 구조를 다시 짜지 않아도 된다.

예산이 거의 없거나 빨리 팀에 보여 주는 게 먼저라면 **A로 먼저 띄우고 C로 옮기는** 길도 있다. 1장의 "바꿈" 항목(주소 `.env`화, 저장소 추상화 등)은 A에서도 해 두면 C로 옮길 때 그대로 쓸 수 있다. **B는 추천하지 않는다.**

## 5. Render 무료 정책과 유료 전환 기준

### 확인한 정책 (2026-11-03, 공식 문서 https://render.com/docs/free — 페이지에 갱신 날짜 표시 없음)

| 항목 | 공식 문서 내용 | 말모아에 주는 뜻 |
|---|---|---|
| 사용 시간 한도 | 워크스페이스마다 한 달 **750 무료 인스턴스 시간**. 다 쓰면 그 달 말까지 **모든 무료 웹 서비스가 정지**. 남은 시간은 넘어가지 않음 | 말모아·meerkit 이 같은 워크스페이스면 함께 씀. 둘 다 하루 종일 깨우면(약 1,440시간) 모자람 → 둘 다 **근무 시간에만** 깨움 (약 528시간) |
| 잠드는 기준 | **15분 동안 들어오는 요청이 없으면** 잠듦. HTTP 요청과 기존 연결의 WebSocket 메시지가 요청으로 침. 잠든 동안 `/robots.txt` 요청은 깨우지 않음 | 10분 간격 깨우기면 근무 시간에는 잠들지 않음 |
| 깨어나는 시간 | 다음 HTTP 요청이나 새 WebSocket 연결에 깨어나며 **약 1분** | 근무 시간 밖 첫 접속은 최대 1분 기다릴 수 있음 |
| 재시작 | 무료 서비스는 **언제든 재시작될 수 있음** | 대기열은 DB, 중단된 작업은 생존 신호로 복구 (5단계) |
| 디스크 | 재배포·재시작·잠들 때 **파일 변경이 사라짐** | 원본·원문·회의록·구간 메모는 저장소에. 디스크는 잠깐 쓰는 임시 파일만 |
| 기타 한도 | 대역폭·빌드 시간이 포함량에 포함. 결제 수단 없이 대역폭을 다 쓰면 그 달 무료 서비스 정지, 빌드 시간을 다 쓰면 새 빌드 중지. 외부로 나가는 트래픽이 지나치게 많은 무료 서비스는 정지될 수 있음 | 원본 음성 재생·다운로드도 대역폭을 씀 |
| 무료 Postgres | 만든 지 **30일 뒤 만료**, 14일 안에 유료로 안 바꾸면 데이터와 함께 삭제, 백업 없음 | 말모아 DB 는 Render 가 아니라 Supabase |
| **깨우기 요청 허용 여부** | 무료 문서에는 깨우기(ping)·cron 에 대한 언급이 없다. 이용 정책(https://render.com/acceptable-use) 본문은 이번에 읽어 오지 못했다. 커뮤니티 답변 중에는 "무료 서비스를 억지로 깨워 두는 것은 남용"이라는 의견이 있다(공식 답변 아님) | **확인 못 함.** 근무 시간에만, 10분 간격으로 최소화한다. Render 에서 경고·정지가 오면 바로 유료로 바꾼다 (아래 기준) |

요청 시간 제한(약 100분)은 공식 문서가 아니라 Render 지원팀의 커뮤니티 답변 기준이다.

### 유료 전환 기준

아래 중 하나라도 생기면 말모아 백엔드를 Render 유료 인스턴스로 바꾼다 (전환 전에 그때의 요금을 공식 페이지에서 확인).

| # | 기준 | 확인 방법 |
|---|---|---|
| 1 | Render 에서 깨우기 요청에 대한 경고·정지 안내가 옴 | 메일·대시보드 |
| 2 | 한 달 무료 시간 사용량이 600시간(80%)을 넘음 | Render 대시보드 사용량 |
| 3 | 근무 시간 밖에도 매일 쓰게 됨 (아침 첫 접속 1분 대기가 잦아 불편) | 팀 의견 |
| 4 | 탭을 닫아도 알려 주는 기능(휴대폰 푸시 알림)을 붙임 — 서버가 늘 깨어 있어야 함 | 기능 결정 |
| 5 | 무료 서버 재시작으로 회의록 작성이 자주 끊김 (작업의 `attempts`가 2 이상인 일이 한 달 3번 넘음) | DB `jobs.attempts` |
| 6 | 대역폭·빌드 시간 한도 경고 | Render 대시보드 |
| 7 | 외부 공개 (팀 밖 사용자) | 배포 결정 |

meerkit 백엔드도 같은 근무 시간에 깨운다. 정지되면 같은 워크스페이스의 두 서버가 함께 멈추므로 1번 기준은 바로 적용한다.
