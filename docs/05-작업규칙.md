# 05. 작업 규칙 (AI 작업자용)

## 반드시 지킬 것

1. **`CLAUDE.md`가 최우선.** 단계별로 진행하고, 수정 전에 목적을 설명하고, 사용자 확인을 받는다.
2. **실행하지 않은 테스트를 성공했다고 보고하지 않는다.** 확인 못 한 것은 "확인 못 함"이라고 쓴다.
3. **사용자에게 보이는 글은 한국어.** 화면 문구·오류 메시지·진행 안내 모두. 오류는 `{"detail": "한국어 문장"}`.
4. **기존 파일을 임의로 삭제·덮어쓰지 않는다.** 이 폴더는 Git 저장소가 아니다 → 되돌리기 어렵다. 큰 변경 전에는 백업.
5. **`backend/storage/`는 사용자의 실제 회의 데이터.** 테스트로 오염시키지 말 것. 시험은 별도 포트·별도 DB(`malmoa_test`)·임시 storage로.
6. **비밀은 `backend/.env`에만.** API 키·DB 비밀번호·SECRET_KEY를 코드·문서·프런트에 쓰지 않는다. 음성·원문을 외부로 보내지 않는다.
7. **유료 서비스 가입·결제 금지.** API 호출이 늘어나는 변경은 비용을 안내한다.
8. **연결되지 않은 버튼을 만들지 않는다.**
9. **`~/Desktop/Malmoa-design`은 별도 프로젝트.** 사용자가 "이 프로젝트는 꼭 그대로 남기라"고 했다. 말모아 수정 때 같이 바꾸지 말고, 바꿔야 하면 따로 확인.

## 코드 관례

### 백엔드
- 패키지는 `uv add`, 실행은 `uv run …` 또는 `backend/.venv/bin/python`. **시스템 python3(3.14)로 실행하지 말 것**
- DB 스키마 변경은 반드시 Alembic: `cd backend && uv run alembic revision --autogenerate -m "설명"` → `uv run alembic upgrade head`
- 스키마는 `CamelModel` 상속 (JSON camelCase). 새 API는 `response_model`과 `responses=ERRORS` 지정
- 작업 접근은 항상 `_get_job(request, job_id, user)` 사용 (UUID 검증 + 사용자 범위)
- 긴 처리는 API에서 직접 하지 말고 DB 대기열에 넣는다(`JobStore.enqueue` + `worker.wake()`). 서버 메모리·서버 디스크에 상태를 두지 않는다 (무료 서버는 언제든 재시작). 처리 함수는 구간별로 저장소에 저장해 재개 가능하게
- 사용자에게 보여 줄 오류는 전용 예외(`TranscribeError`, `MinutesError`, `OcrError`) 메시지로, 예상 못 한 오류는 로그 + 일반 안내
- 파일 쓰기는 `write_json_atomic` 또는 임시 파일 → `replace`
- 테스트: `cd backend && uv run pytest` (conftest가 `malmoa_test` DB와 임시 storage 사용, `X-Test-User` 헤더로 사용자를 바꿔 사용자별 분리를 시험)

### 프런트엔드
- **Next.js 16은 학습 데이터와 다르다.** 코드 쓰기 전에 `frontend/node_modules/next/dist/docs/`의 관련 가이드를 읽는다 (`frontend/AGENTS.md`)
- `cacheComponents` 켜짐: 동적 부분은 `<Suspense>`로 감싼다. `(app)/layout.tsx`가 AppShell을 Suspense로 감싸는 구조
- 동적 경로 params는 Promise (`params.then(...)` / `use(params)`)
- `next.config.ts`의 `experimental.instantInsights.validationLevel: 'manual-warning'`은 의도적 설정 (브라우저 전용 코드 검증 오류 회피)
- 서버 데이터는 TanStack Query 훅(`hooks/queries.ts`)으로만. 직접 fetch 금지 → `lib/api.ts` 함수 추가
- 백엔드 스키마를 바꾸면 `lib/types.ts`도 같이 바꾼다
- 회의록 규칙(`backend/app/services/minutes.py`)과 복사용 요청문(`lib/minutesPrompt.ts`)은 같은 내용을 유지한다 (참석자 규칙 포함)
- UI는 `components/ui/`(shadcn) 조합으로. 새 shadcn 컴포넌트는 `npx shadcn@latest add <이름>`
- `useEffect` 안에서 setState를 바로 하면 lint 오류 → promise `then`이나 이벤트 핸들러로
- 화살표 함수 `useEffect(() => window.scrollTo(0,0))`처럼 값을 반환하면 cleanup으로 오해되어 흰 화면이 난 적 있음 → 블록 본문 사용
- 검사: `cd frontend && npm run lint`, `npx tsc --noEmit`, `npm run build`

## 실행·확인

```bash
./start.sh                      # 전체 실행 (포트 8010·3001이 이미 쓰이면 중단)
backend/scripts/db.sh status    # DB 상태
curl http://localhost:8010/api/health
```

화면 시험은 실제 데이터를 건드리지 않도록 백엔드를 다른 포트(예: 8003)와 임시 `STORAGE_DIR`·테스트 DB로 띄우고 프런트도 다른 포트로 띄워 확인해 왔다. 브라우저 자동 시험은 headless Chrome + CDP(가짜 마이크 `--use-fake-device-for-media-stream`)로 했다. 클립보드는 실제 마우스 이벤트로 눌러야 복사된다.

## 알려진 문제와 남은 과제

| 항목 | 상태 |
|---|---|
| **받아쓰기 정확도** | `small` 모델은 실제 회의에서 알아보기 어려울 정도로 부정확했다. 원인: 작은 모델, 전문 용어 미제공, 환각(외국 문자·짧은 반복), 5분 구간마다 문맥 끊김, 작은 녹음 음량(약 -29dB). mlx-whisper `large-v3` + 용어집(`initial_prompt`) + 환각 필터로 크게 개선됨을 시험으로 확인. **앱에는 아직 반영 안 됨** |
| 기존 회의 재변환 | 1시간 43분 회의 등 2건을 large-v3로 다시 변환하는 스크립트는 준비됨(세션 임시 폴더). 이전 시도에서 MLX 메모리 누적으로 중단 → 캐시 제한·재개 추가. **사용자 승인 대기** |
| AI 회의록 | 코드는 완성·테스트됨. `.env`에 API 키가 없어 실제로는 복사 방식 사용 중 |
| 로그인 | 자체 로그인은 2026-11-02 삭제. npm 로그인 라이브러리로 연결 예정 — 라이브러리는 사용자가 정한다 |
| 삭제 기능 | 작업 삭제 있음(2026-10-28). 새 파일 종류를 작업에 추가하면 `jobs.py`의 `job_files()`에도 넣을 것 |
| 10일 사용 파일 관리 | 2시간 녹음 기준 용량·정리 정책은 아직 검증 안 됨 |
| 실기기 시험 | 실제 Windows 노트북·휴대폰 카메라·실제 화이트보드 사진은 사용자 확인 필요 |
| 화자 분리 | 미구현 (참석자 등록은 있음 — 누가 말했는지는 모름) |
| 참석자 → AI 담당자 맞추기 | 요청문 규칙은 단위 테스트로 확인. 실제 AI 응답으로는 확인 못 함 (API 키 없음) |

## 정확도 개선을 앱에 반영한다면 (참고)

시험에서 효과가 있었던 것: `large-v3`(또는 turbo) 모델, Apple Silicon에서는 mlx-whisper, 회의 용어집을 `initial_prompt`로 짧은 조각마다 제공, `no_speech_prob`·`compression_ratio`·외국 문자·연속 중복 필터, MLX는 `mx.set_cache_limit`·`clear_cache`로 메모리 관리. 모델이 커지면 처리 시간·메모리가 늘어나므로 설정으로 선택 가능하게 하고 사용자에게 확인받을 것.
