## 1. 받아쓰기·변환

### #1 실제 회의 받아쓰기가 부정확함 🔴 (2026-10-23)

- **증상:** `small` 모델로 변환한 실제 회의 원문이 알아보기 어려울 정도로 틀림. 외국 문자나 짧은 말이 반복되는 줄도 섞임.
- **원인 (분석 결과)**
  1. 작은 모델(`small`)
  2. 회의 전문 용어(미어킷·매무새 등 고유명사)를 모델에 알려 주지 않음
  3. 환각: 조용한 구간에서 외국 문자, 같은 문장 반복
  4. 5분 구간마다 잘라서 변환하므로 앞 구간의 문맥이 끊김
  5. 녹음 음량이 작음 (약 -29dB)
- **확인한 개선 방법 (시험으로 효과 확인)**
  - mlx-whisper `large-v3`(Apple Silicon 가속)
  - 용어집을 `initial_prompt`로 조각마다 제공
  - 환각 거르기: `no_speech_prob`, `compression_ratio`, 외국 문자, 연속 중복
- **상태:** 앱에는 **아직 반영하지 않음**. 모델이 커지면 처리 시간과 메모리가 늘어나므로, 설정에서 고를 수 있게 만들고 사용자 확인을 받은 뒤 반영할 것.
- 참고: `05-작업규칙.md` "정확도 개선을 앱에 반영한다면"

### #2 지난 회의 재변환이 메모리 누적으로 중단됨 🔴 (2026-10-23)

- **증상:** 1시간 43분 회의 등 2건을 large-v3로 다시 변환하던 중 멈춤.
- **원인:** MLX가 구간마다 캐시 메모리를 놓지 않고 계속 쌓음.
- **조치:** `mx.set_cache_limit`·`clear_cache`로 메모리를 제한하고, 끊긴 구간부터 다시 하도록 재개 기능을 넣음. 스크립트는 세션 임시 폴더에 있음.
- **상태:** 실행은 **사용자 승인 대기**.

### #3 화이트보드 사진에서 일부 글자를 못 읽음 🟡 (2026-10-24)

- **증상:** 겹쳐 쓴 제목 "미어킷 출시 일정"이 "당되어킷절사활정"으로 읽힘.
- **원인:** Apple Vision 글자 인식은 또박또박 쓴 줄은 잘 읽지만, 겹치거나 흘려 쓴 글, 기울어진 글은 틀리거나 빠뜨림. 도형·화살표의 의미는 읽지 못함.
- **조치:** 확신이 낮은 줄은 노란색과 "확인 필요"로 표시.
  - 사진을 이해하는 AI 모델로 읽으면 더 정확함. 하지만 사진이 외부로 나가고 API 키가 필요해서 이번 범위에서는 뺌.
- **남은 일:** 빛 반사가 있거나 비스듬히 찍은 실제 화이트보드 사진으로는 아직 시험하지 않음.

## 2. 녹음·자동 녹음

### #4 화면을 옮기면 녹음이 멈춤 ✅ (2026-10-24)

- **증상:** 녹음 중에 "결과 보기"를 누르면 녹음이 끊김.
- **원인:** 녹음기가 홈 화면 안에만 있었음. 홈 화면이 닫히면 녹음기도 함께 꺼짐.
- **조치:** 녹음기를 모든 화면이 함께 쓰는 공통 틀로 옮김. 녹음 중에도 화면을 오갈 수 있고, 오른쪽 아래 녹음 막대로 조작함.
- **남은 제한:** 브라우저 탭을 닫거나 새로고침하면 녹음은 멈춤.
  - 닫기 전에 경고가 나옴.
  - 10초마다 브라우저 저장소에 저장해 두므로 "불러오기"로 그때까지의 녹음은 되살릴 수 있음.

### #5 자동 녹음이 시작되지 않음 ✅ (2026-10-29)

- **증상:** 일정 시작 시각이 돼도 자동 녹음이 시작되지 않음. 서버 로그에 화면의 생존 신호(heartbeat)도 없음.
- **원인**
  - 개발 모드(React StrictMode)는 화면 효과를 "실행 → 정리 → 다시 실행"함.
  - 첫 실행에서 요청한 탭 잠금(`malmoa-auto-record`)이 정리가 끝난 뒤에 늦게 승인됨. 그 잠금은 아무도 놓지 않은 채 남음.
  - 그래서 "자동 녹음 담당 탭"이 하나도 없는 상태가 되어 스케줄러가 멈춤.
- **조치:** `holdLock()`이 이미 정리된 화면에 늦게 온 승인을 받으면 곧바로 놓도록 고침. 같은 위험이 있던 `malmoa-recording` 잠금도 함께 고침.
- **교훈:** 배포용 빌드에는 StrictMode가 없어서 처음 시험에서는 이 문제가 드러나지 않았음. 개발 모드 시험본(5182)으로 재현한 뒤 고침.

### #6 "브라우저 저장소를 열 수 없습니다" ✅ (2026-10-29, 원인은 추정)

- **증상:** 시크릿 창이 아닌데도 녹음을 시작할 때 이 안내가 뜸.
- **원인 (가장 유력):** 처음 연 IndexedDB 연결을 계속 다시 쓰고 있었음. 탭을 오래 열어 두면 브라우저가 이 연결을 닫을 수 있음.
- **조치**
  - 연결이 닫혀 있으면 새로 열고 한 번 더 시도함.
  - 그래도 실패하면 오류 문구 끝 괄호에 실제 원인 이름(예: `InvalidStateError`)을 함께 보여 줌.
  - 토스트에 닫기(✕) 단추를 추가함.
- **확인:** 저장소 연결을 강제로 닫은 뒤에도 자동 녹음이 정상 시작됨.
- **확인 못 함:** 사용자 브라우저에서 실제로 연결이 닫힌 이유. 같은 오류가 다시 나면 괄호 안의 원인 이름을 기록할 것.

### #7 녹음 중 일정을 지우면 변환이 막힘 ✅ (2026-10-29)

- **증상:** 녹음을 마치고 보냈는데 변환이 시작되지 않음. 서버 로그에 400이 여러 번 찍힘.
- **원인:** 녹음은 시작한 일정의 ID를 들고 있다가 파일을 보낼 때 `event_id`로 함께 넘김. 그 일정이 이미 지워져 있으면 서버가 "연결할 일정을 찾을 수 없습니다"(400)로 파일 자체를 거절함.
- **조치:** 없어진 일정이면 일정 연결만 빼고 파일은 받도록 고침(`api/jobs.py`의 `_own_event`). 다른 사람의 일정이거나 이상한 ID는 그대로 400. 테스트를 추가함.

### #8 시험 브라우저가 실제 자동 녹음을 가로챔 ✅ (2026-10-29, 시험 중 사고)

- **증상:** 실제 앱(3001)에서 삭제 단추를 시험하던 중 사용자 일정 "멘토링"의 자동 녹음 시각이 됨. 시험용 headless Chrome이 가짜 마이크로 녹음을 시작하고 서버에 "시작됨"으로 보고함.
- **원인:** 시험 브라우저는 별도 프로필이라 사용자 탭과 잠금을 나누지 않음. 그래서 시험 브라우저가 따로 "담당 탭"이 됨.
- **조치:** DB에서 그 일정을 "대기(armed)"로 되돌림.
- **재발 방지 규칙**
  - 실제 앱 3001은 시험 브라우저로 열지 않음.
  - 화면 시험은 시험 환경에서만 함: 프런트 5181/5182 → 백엔드 8003, `malmoa_test` DB.
  - 실제 앱 확인이 꼭 필요하면 먼저 시작 ±10분 안의 자동 녹음 일정이 없는지 봄.

### #9 IP 주소로 접속하면 녹음이 안 됨 🟡 (구조상 한계)

- **증상:** 다른 기기에서 `http://192.168.x.x:3001`로 열면 파일 업로드는 되지만 녹음 단추와 자동 녹음이 동작하지 않음.
- **원인:** 브라우저는 보안 때문에 `localhost`이거나 `https://` 주소일 때만 마이크를 허용함.
- **우회:** 다른 노트북에서 녹음할 때는 별도 폴더 `~/Desktop/Malmoa-design`의 https 녹음 서버를 씀.

### #10 Mac 잠자기 중에는 자동 녹음이 안 됨 🟡 (2026-10-29 결정)

- 잠자기를 막는 `caffeinate`는 쓰지 않기로 결정함.
- 일정 창과 시작 5분 전 사전 점검 알림에 "Mac이 잠자기 상태면 녹음되지 않습니다"라고 안내함.
- 시작 시각 + 10분 안에 깨어나면 그때 시작함.

### 29. 녹음 중 로그인이 풀리면 녹음이 멈춤 (2026-11-03 ✅)

- **증상(코드로 확인):** 녹음 중에도 화면은 30초마다 알림을 확인한다. 액세스 토큰(30분)이 만료되면 meerkit에 갱신을 요청하는데, 갱신이 실패하면(로그인 서버가 잠들어 깨는 중·꺼짐·인터넷 끊김) meerkit 코드가 토큰을 지운다 → AppShell이 로그인 창으로 바꿈 → 녹음기 부품이 빠지며 `recorder.stop()` → 그 뒤 회의는 녹음되지 않음 (그때까지 녹음은 IndexedDB에 남음).
- **계기:** 배포에서 meerkit을 Render 무료로 두면 잠들었다 깨는 동안 갱신이 실패할 수 있다.
- **조치:** 녹음기가 쓰이는 중이면(`stores/recorderBusy.ts`) 로그인이 풀려도 바탕화면·녹음기를 그대로 두고 그 위에 로그인 창(`SessionLostOverlay`)을 띄움. 20초마다 갱신을 다시 시도해 로그인 서버가 돌아오면 저절로 다시 로그인. meerkit 코드는 고치지 않음.

### #37 `/api` 프록시가 업로드 본문을 10MB 에서 잘라 15MB 업로드 실패 ✅ (2026-11-03, 통합 단계 3)

### #38 `/jobs/[id]` 운영 빌드가 "metadata is blocked" 로 실패 ✅ (2026-11-03, 통합 단계 3)

- **증상:** `npm run build` 중 `Route "/jobs/[id]": Next.js encountered uncached or runtime data in generateMetadata()` → 빌드 중단. 페이지에 `generateMetadata`는 없다. legacy 는 운영 빌드를 해 본 적이 없어 몰랐다.
- **원인:** Cache Components 에서 주소 값(params)이 있는 화면은 메타데이터가 요청 때 정해지는데, 페이지 내용이 모두 미리 그려질 수 있으면 오류로 본다. 말모아 화면은 `AppShell`이 브라우저에서만 그려서(`use(browser())`) 서버 미리 렌더에 페이지가 들어가지 않으므로, 페이지 안에 둔 동적 표시도 보이지 않았다.
- **해결:** `app/(service)/layout.tsx`의 `AppShell` **바깥**에 `<Suspense><DynamicMarker /></Suspense>`(`await connection()`). 말모아 화면은 원래 브라우저 전용이라 잃는 것 없음.

### #42 Mac 작업자가 DB 비밀 없이는 켜지지 않음 ✅ (2026-11-03, 통합 단계 5-3)

### #41 업로드 서명 주소가 예전 SigV2 로 만들어짐 ✅ (2026-11-03, 통합 단계 5-2)

- **증상:** 서명 주소에 `AWSAccessKeyId=…&Signature=…&Expires=…`(SigV2). 크기가 서명에 들어가지 않고, R2 는 SigV4 만 받는다.
- **원인:** boto3 클라이언트에 `signature_version`을 정하지 않아 사용자 지정 주소(endpoint)에서 예전 방식이 골라졌다.
- **해결:** `S3Store`의 `Config(signature_version="s3v4")`. 시험이 `X-Amz-Algorithm=AWS4-HMAC-SHA256`, 서명 헤더에 `content-length`·`content-type`·`host`가 있는지 확인. moto 는 서명을 검사하지 않으므로 "같은 주소로 GET 거절"은 단계 6 에서 R2 로 확인.
