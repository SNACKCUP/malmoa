## 할 일 (순서대로, 각 항목 끝나면 테스트·문서)

### 5-1. 말모아 사용 승인 (역할) — 결정 4

- 백엔드: 말모아 API 의 로그인 확인(`features/malmoa/deps.py`의 `CurrentUser`)에 "승인 역할" 검사를 더한다. 없으면 **403** `{"code": "MALMOA_NOT_APPROVED"}`. `/api/health`는 그대로 공개. 킷 코드는 고치지 않는다.
- 프런트: AppShell 이 로그인 뒤 역할을 보고, 없으면 98 창 **"승인 대기"** 화면(안내 · 내 정보 · 로그아웃)만 보여 준다. 관리자는 회원 관리에서 역할을 준다.
- 지금 회원: admin(MASTER) 그대로 사용, test01·malmoatest(VIEWER)는 승인 전까지 막힘.
- 약관 4조("승인한 회원만")와 실제 동작이 이때 맞춰진다.
- 테스트: 승인 없는 회원 403, 승인 역할 200, MASTER 200, 역할 바꾸면 바로 반영.

### 5-2. R2 직접 업로드 (업로드 전용 서명 주소)

- 흐름: ① `POST /api/jobs/upload-url` {파일명, 크기, 종류} → 서버가 형식·크기(`MAX_UPLOAD_MB`, 배포 50)를 검사하고 "올리는 중" 작업과 **PUT 전용 서명 주소**(10분, 크기 고정 `Content-Length` 서명) 발급 → ② 브라우저가 R2 로 PUT (진행률 표시) → ③ `POST /api/jobs/{id}/uploaded` → 서버가 버킷에서 크기 확인 후 작업 확정·변환 대기열.
- 비공개 원칙 유지: 내려받기 서명 주소는 만들지 않는다(원본·원문·회의록은 지금처럼 로그인 확인 뒤 백엔드가 전달).
- 끝나지 않은 업로드(②에서 멈춤)는 하루 뒤 작업·객체 삭제.
- 로컬(`MALMOA_FILES_BACKEND=local`)은 지금 방식(`POST /api/jobs` multipart) 유지 — 화면은 서버가 알려 주는 방식으로 고른다.
- 녹음기·업로드 화면·화이트보드 사진 모두 같은 흐름.
- R2 버킷 CORS(화면 주소에서 PUT 허용)는 단계 6 설정, 단계 5 에서는 moto/MinIO 로 시험.
- 테스트: 크기 초과·형식 거부, 서명 주소로 PUT 후 확정, 크기 다르면 거부, 남의 작업 확정 거부, 끝나지 않은 업로드 정리.

### 5-3. Mac 작업자 API — 결정 5 (가)

- 서버(Render)는 `WORKER_TASKS=["minutes"]`(AI 회의록만), Mac 은 음성 인식·사진 글자 인식만.
- 작업자 인증: `Authorization: Bearer <MALMOA_WORKER_TOKEN>` — 회원이 아닌 작업자 전용 열쇠. 서버 `.env`에는 해시만 두고 비교는 상수 시간. Mac 에는 이 열쇠와 API 주소만 (DB 비밀번호·R2 키 없음).
- API (`/api/worker/…`): 일 가져가기(claim) · 원본 받기(백엔드가 R2 에서 읽어 전달) · 진행 상황·생존 신호 · 원문 올리기 · 실패 알리기. 내부적으로는 지금의 DB 대기열(`claim`·`heartbeat`·`release`·`recover_stale`)을 그대로 쓴다.
- Mac 작업자 프로그램 `backend/scripts/malmoa_worker.py` (Whisper·Vision 은 `worker` 의존성 그룹): 조회 시간 설정(기본 **평일 08~20시, Asia/Seoul** — cron 깨우기와 같게), 평소 1~2분 간격, 서버가 응답 없으면 2→4→8→최대 15분, 시간 밖에는 조회하지 않음(서버를 깨우지 않으려고).
- 수동 실행 (결정 D): 시간 밖에도 바로 처리.
- 테스트: 틀린 열쇠 401, 회원 토큰으로 작업자 API 403, 같은 작업 두 작업자가 못 가져감, 끊기면 다시 대기열, 원문 올리면 회원 화면에 표시, 작업 전용 파일은 끝나면 Mac 에서 삭제.

### 5-4. 서버(Linux)에서 Mac 전용 기능 끄기

- 사진 글자 인식: 서버는 하지 않음(작업자 몫). 서버에서 실수로 돌면 "Mac 작업자에서만" 오류.
- Mac 알림: 운영에서는 끔(`MAC_NOTIFICATIONS=false`), 일정 알람은 지금처럼 화면 알림.
- Mac 캘린더 내보내기: macOS 가 아니면 설정 화면에서 숨기고 ICS 구독(5-6)을 보여 준다.

### 5-5. PDF 무료 한글 글꼴

- macOS 글꼴이 없으면 저장소에 넣은 **Noto Sans KR**(SIL Open Font License, 무료·재배포 가능)을 쓴다. 글꼴 파일은 `backend/app/features/malmoa/fonts/`(라이선스 파일 함께). Mac 에서는 지금처럼 시스템 글꼴도 가능.
- 테스트: 시스템 글꼴 없이 한글 PDF 생성.

### 5-6. ICS 구독 (아이폰 일정 알림) — 결정 C

- 회원마다 비밀 구독 주소 `https://<API>/api/calendar/<비밀값>.ics`(캘린더 앱은 로그인 헤더를 보낼 수 없어 주소 자체가 열쇠). 설정 화면에서 만들기·다시 만들기(예전 주소 무효)·끄기.
- 넣는 내용(결정 C): 제목·시각·장소·메모·참석자·알람. 녹음·원문·회의록은 넣지 않는다. 설정 화면에 "주소를 아는 사람은 메모·참석자까지 볼 수 있음" 안내.
- 주의: 아이폰이 구독 캘린더를 새로 고치는 주기는 iOS 가 정함(즉시 반영 아님), 구독 캘린더 알람이 울리는지는 실기기 확인 필요.
- 테스트: 틀린 주소 404, 다시 만들면 예전 주소 404, 다른 회원 일정 안 섞임, 결정 C 에서 뺀 항목이 없음.

### 5-7. 탈퇴 회원 말모아 데이터 정리 — 결정 B

- 서버 안의 하루 한 번 정리 작업(알람 검사기와 같은 방식, 서버가 깨어 있을 때 돈다): 탈퇴한 지 **30일**(결정 B, 설정값)이 지난 회원의 작업(원본·원문·회의록 파일 포함)·참석자·일정·AI 설정·사용량·프로필 삭제.
- 미리보기·실행 기록을 로그에 남기고 개수만 적는다(내용 없음).
- 개인정보 처리방침 3번 표의 "탈퇴한 회원의 녹음… 시점"을 이 값으로 채운다.
- 테스트: 기간 전 남음, 기간 뒤 DB·파일 모두 삭제, 다른 회원 영향 없음.

### 5-8. 운영 설정 검사

- 운영 모드에서 서버가 켜질 때 말모아 설정을 검사하고 틀리면 켜지지 않음(이유 표시): `SECRET_KEY` 있음, `MALMOA_FILES_BACKEND=s3`·버킷 접속, `MAX_UPLOAD_MB` ≤ 50, `WORKER_TASKS`에 `transcribe` 없음, `MAC_NOTIFICATIONS=false`, `MALMOA_WORKER_TOKEN` 해시 있음.
- `.env.example`에 말모아 항목과 설명 추가. meerkit `env check --prod`와 함께 단계 6 에서 실행.
- 깨우기 cron 주소는 하나: meerkit `/health/ready`(DB 확인 포함). 말모아 `/api/health`도 그대로 둔다.

- 날짜 문서(이 문서 결과), 통합계획 단계 5, 진행표, 기능명세(승인 대기·직접 업로드·ICS·작업자), API 명세(새 API), 구조, 트러블이슈, 개인정보 처리방침의 "확정 필요" 칸 중 이 단계에서 정해지는 것(탈퇴 정리 시점).

## 되돌리기

항목마다 커밋을 나눈다. DB 를 바꾸는 항목(5-2 "올리는 중" 상태, 5-6 ICS 비밀값 열, 5-7)은 Alembic 마이그레이션으로 하고, 적용 전 `legacy/Malmoa/backups/`에 DB 덤프.
