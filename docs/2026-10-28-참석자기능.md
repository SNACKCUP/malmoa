# 회의 참석자 기능 (2026-10-28)

회의마다 누가 참석했는지 등록하고 화면·회의록에 표시하는 기능입니다.

## 1. 요청

> 회의참석자를 등록해서 회의의 참석자 표현을 해줘. 그리고 문서화(md)

## 2. 설계 결정

| 결정 | 이유 |
|---|---|
| **명단(people)과 회의별 참석자(jobs.attendees)를 나눈다** | 자주 오는 사람은 한 번 등록하고 회의마다 눌러서 고르면 됨. 처음 오는 사람은 그 자리에서 이름을 적어 추가 |
| 회의별 참석자는 **이름·소속을 복사해 저장**(JSON)하고 명단 ID로 연결하지 않는다 | 명단에서 사람을 고치거나 지워도 지난 회의 기록이 바뀌지 않아야 함. 회의록은 그 시점의 기록 |
| 녹음 중에도 참석자를 고를 수 있다 | 늦게 오는 사람이 있음. 녹음 칸의 초안은 localStorage에 두어 브라우저가 갑자기 닫혀도 녹음 복구와 함께 남음 |
| 새로 적은 이름은 **명단에도 자동 저장** | 다음 회의에서 다시 적지 않도록 |
| 회의록의 "참석자" 줄은 **AI가 쓰지 않고** 등록된 명단을 그대로 넣는다 | 지어내기 방지 원칙(CLAUDE.md). 등록이 없으면 `확인 필요 (등록되지 않음)` |
| AI에는 참석자 명단을 주되 **담당자 이름 표기를 맞추는 데만** 쓰게 한다 | 음성 인식이 이름을 틀리게 적는 경우가 많음. 단, 원문에 이름이 없는 할 일에 참석자를 담당자로 넣거나 발언자를 추측하면 안 됨 |
| 화자 분리(누가 말했는지)는 하지 않는다 | 이번 범위가 아님. 참석자 등록과는 별개 기능 |

## 3. 화면

| 위치 | 동작 |
|---|---|
| 홈 › 직접 녹음 › **이번 회의 참석자** | 녹음 전·중·후 모두 표시. 명단 이름 버튼 누르기(+ "모두 추가"), 이름 + 소속·직책(선택) 적고 **추가**, 이름표의 ✕로 빼기. **텍스트로 변환**을 누르면 녹음과 함께 서버에 저장되고 초안은 비워짐 |
| 이름표 (녹음 칸·결과 고치기) | **이름을 누르면 그 자리에 직책 칸**이 열림. Enter·칸 밖 누르기 = 저장, Esc = 취소. 직책이 없으면 이름 옆에 `+직책` 표시. 명단에 있는 사람이면 명단의 직책도 함께 바뀜(다음 회의부터 자동으로 들어감) |
| 결과 보기 머리글 | `참석자 N명` + 이름표. **고치기 / 참석자 등록** → 같은 고르기 화면 → **저장 / 취소**. 회의록이 이미 있으면 "이미 만든 회의록 본문은 바뀌지 않음" 안내 |
| 작업 목록 | 파일 정보 아래에 참석자 이름. 전체 목록 검색이 **파일명·참석자**를 함께 찾음 |
| 설정 › **참석자 명단** (`/settings#people`) | 이름·소속 등록, 목록, **이름 눌러 직책 고치기**(`PUT /api/people/{id}`), 지우기. "지워도 지난 회의 기록은 그대로" 안내 |
| 사용 안내 | 녹음 전 단계와 준비 목록에 참석자 등록 방법 추가 |
| 회의록 요청문과 함께 복사 | `[참석자]` 목록과 사용 규칙이 요청문에 들어감 |

파일 업로드 칸에는 참석자 입력을 넣지 않았습니다(지난 회의 파일은 올린 뒤 결과 화면에서 등록).

## 4. 데이터

```text
people                                   jobs
├ id          UUID PK                    ├ …
├ user_id     → users.id (CASCADE)       └ attendees  JSONB, 기본 '[]'
├ name        varchar(50)                     [{"name": "홍길동", "role": "기획팀"},
├ role        varchar(50) NULL                 {"name": "강감찬", "role": null}]
├ created_at
└ UNIQUE (user_id, name)
```

- 마이그레이션: `backend/migrations/versions/2026_10_28_0951-a09db2f85c3a_meeting_attendees_and_people.py`
- 이름·소속은 앞뒤 공백 제거, 연속 공백 하나로, 1~50자. 빈 소속은 `null`
- 한 회의 최대 100명. 같은 이름은 한 번만(먼저 나온 것 유지)
- 로그인을 켜서 첫 가입자가 로컬 계정 작업을 넘겨받을 때 **명단도 함께** 넘어감 (`adopt_local_user`)
- 적용 전 DB 백업: `backups/db-before-attendees-2026-10-28.dump` (Git 제외)

## 5. API

| 메서드·경로 | 요청 | 응답 | 오류 |
|---|---|---|---|
| `POST /api/jobs` | 기존 + form `attendees` = JSON 배열 문자열 (선택) | `Job` (`attendees` 포함) | 400 형식 오류 ("참석자 형식이 올바르지 않습니다…"), 파일은 저장하지 않음 |
| `PUT /api/jobs/{id}/attendees` | `{"attendees": [{"name", "role"}]}` 전체 교체 | `Job` | 404, 422 |
| `GET /api/people` | — | `{"people": [{id, name, role, createdAt}]}` 이름순 | |
| `POST /api/people` | `{"name", "role"}` | 201 `Person` | 409 이미 있는 이름, 422 |
| `PUT /api/people/{id}` | `{"name", "role"}` | `Person` | 404, 409 |
| `DELETE /api/people/{id}` | — | 204 | 404 |

모든 `Job` 응답에 `attendees: Attendee[]`가 추가되었습니다. 다른 사용자의 명단·작업은 404.

## 6. 회의록 반영

**AI 회의록** (`backend/app/services/minutes.py`)

```markdown
# 주간 회의
- 녹음 등록: 2026-10-28 10:00
- 녹음 길이: 10분
- 참석자: 홍길동(기획팀), 강감찬        ← 등록 없으면 "확인 필요 (등록되지 않음)"
- 원본 파일: 회의.m4a
```

AI 요청문(한 번에 작성·구간 메모·통합 모두)에 다음을 덧붙입니다.

```text
<참석자>
- 홍길동(기획팀)
</참석자>
참석자 명단 사용 규칙:
- 원문에 나온 이름이 참석자와 같은 사람으로 보이면 담당자를 참석자 명단의 이름으로 적는다. (음성 인식으로 이름이 조금 틀렸을 수 있다)
- 원문에서 이름이 나오지 않은 할 일에 참석자를 담당자로 넣지 않는다. 그런 경우는 "확인 필요".
- 원문에 누가 말했는지 표시가 없으므로 발언자를 추측하지 않는다.
```

**복사용 요청문** (`frontend/src/lib/minutesPrompt.ts`)도 같은 규칙 + "회의록 맨 위에 참석자 명단을 그대로 적어 주세요."

참석자를 나중에 고쳐도 **이미 만든 회의록 본문은 바뀌지 않습니다**(사용자가 편집했을 수 있으므로). 회의록 화면에서 직접 고치거나 다시 만들면 반영됩니다.
