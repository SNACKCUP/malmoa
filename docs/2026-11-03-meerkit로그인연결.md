# 2026-11-03 meerkit 로그인 연결 (로컬, 형태 A)

브랜치 `feat/llm-settings` (커밋 전). 계획: `2026-11-02-meerkit로그인연결-분석.md` 6장, 배포 방향: `2026-11-03-배포목표와결정사항.md`.

## 요청

"meerkit 로그인을 연결해줘. 범위는 로그인·로그아웃·세션 유지까지. 멤버 관리·초대는 이번에 하지 않는다."

정한 것:

- meerkit DB는 5433으로 옮긴다 (말모아 pgserver는 5432 유지).
- 로컬 계정(`local@malmoa.local`) 데이터는 **지정한 회원**에게 넘긴다 (`LEGACY_OWNER_MEERKIT_USER_ID`).
- `users.email` 칸은 지운다 (CLAUDE.md 11절: 사용자 연결은 `meerkit_user_id` 하나).
- 98 OS 화면은 유지한다.

## 구조

```
브라우저 (말모아 프론트 :3001)
 ├─ /api/*  → Next.js rewrites → meerkit 백엔드 :8000   (로그인·토큰 갱신·회원, DB: meerkit Docker :5433)
 └─ NEXT_PUBLIC_API_URL/api/jobs … (Bearer) → 말모아 백엔드 :8010   (토큰 검증만, DB: pgserver :5432)
```

- 액세스 토큰: meerkit이 발급하는 JWT HS256(`sub`=정수 회원 번호, `type=access`, 30분). 브라우저 메모리에만 있다.
- 리프레시 토큰: httpOnly 쿠키 `meerkit_refresh`(경로 `/api/auth`). 그래서 meerkit은 같은 출처(`/api/*` 넘기기)로만 부른다.
- 말모아 백엔드는 meerkit과 같은 `JWT_SECRET_KEY`로 서명만 확인한다. 처음 보는 회원이면 `users` 행을 만든다.

### 4. start.sh, 루트 `.env`

- 순서: meerkit DB(Docker) → meerkit 마이그레이션 → meerkit 백엔드(이미 켜져 있으면 `/health/ready` 확인 후 그대로) → 말모아 DB → `SECRET_KEY`·`JWT_SECRET_KEY` 확인(없으면 meerkit 값 복사, 다르면 멈춤) → 마이그레이션 → 말모아 백엔드(CORS는 프런트 주소) → 프런트.
- 주소·포트·meerkit 위치는 루트 `.env`(`.env.example`)에서. 같은 이름 환경변수가 우선 (시험: `MALMOA_WEB_PORT=5181 MALMOA_API_PORT=8003 NO_OPEN=1`).
- Docker가 꺼져 있으면 안내. Ctrl+C로 이 스크립트가 켠 것만 끈다.
- 고친 예전 버그: 마지막에 `cd frontend` 한 뒤라 종료 때 `backend/scripts/db.sh`를 못 찾았다 → ROOT 기준 경로.

## 검증 (실제로 한 것)

- 백엔드 pytest **76개 통과** (기존 63 + 새 `test_auth.py` 13: 토큰 없음·서명 틀림·만료·refresh 형식·정수 아닌 sub·exp 없음·쓰레기 값 → 401, 만료 문구, 처음 보는 회원 한 번만 생성, 회원별 작업 분리, 지정 회원에게 로컬 계정 넘김(다른 회원이 먼저 로그인해도 안 가져감), 지정 없으면 안 넘김). 시험 DB는 마이그레이션을 base→head로 다시 적용.
- 프런트 `tsc`·`eslint` 통과. `scripts/check-rules.sh` 통과 (킷 무변경, 킷 폴더 원본과 같음, 바뀐 줄에 localhost 없음).
- 실제 DB: 마이그레이션 적용 후 `users`(로컬 계정 1행, `meerkit_user_id` 빈칸)·작업 18개 그대로.
- `start.sh`(5181·8003, meerkit 8001, 브라우저 안 엶): 7단계 순서대로 켜짐, Ctrl+C(프로세스 그룹)로 8001·8003·5181·말모아 DB 종료, 원래 켜져 있던 meerkit DB는 유지.

- headless Chrome(임시 프로필) 캡처: 로그인 창·가입 창이 98 창 안에 98 단추·입력칸으로 그려짐, 로그인 → 바탕화면(👤 이름) → 새로고침 뒤에도 로그인 유지.

## 확인하지 못한 것

- 3001(실제 앱)은 규칙대로 시험 브라우저로 열지 않았다. 8000의 meerkit 백엔드도 재시작 전이라 3001 조합은 시험하지 않음.
- 비밀번호 찾기 메일 → `/reset-password` 링크 흐름, 아이디 찾기 창(98로 고친 `dialog`)은 화면으로 확인하지 않았다.
- 토큰 30분 만료 → 자동 갱신은 백엔드 테스트(만료 401)와 갱신 API로만 확인. 브라우저에서 30분을 기다려 보지는 않음.
- 로컬 데이터 넘기기는 테스트로만 확인. 실제 DB는 관리자(1번)가 3001에서 처음 로그인할 때 넘어간다 (아직 로그인 전).
