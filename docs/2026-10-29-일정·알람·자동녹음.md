# 일정·알람·자동 녹음 (2026-10-29, 설계 — 아직 구현 전)

> 1. 회의나 그 외 일정의 날짜와 시간을 표시하는 캘린더
> 2. 정해진 시간 전에 알람
> 3. 시간이 되면 저절로 녹음 시작

**상태: 1~4단계(일정 DB·API, 캘린더 화면, Mac·화면·아이폰 알람, 자동 녹음) 완료 (2026-10-29).** 결정은 맨 아래 "결정 사항"에 정리했습니다(2026-10-29).
세 기능은 서로 기대고 있습니다: 자동 녹음(3)은 일정(1)의 시작·종료 시각과 알람 검사기(2)를 그대로 씁니다.

## 1. 캘린더

### 화면
- 왼쪽 메뉴에 **캘린더** (`/calendar`). 기본은 **월 보기**, 날짜를 누르면 그날 일정 목록. 주 보기는 나중에
- 일정 추가·수정·삭제 창: 제목, 날짜, 시작·종료 시각(또는 종일), 장소, 메모, 종류(회의/기타), 알람 시점, **자동 녹음**(회의일 때만)
- 회의 일정에는 기존 **참석자 명단**(`people`)에서 참석자를 고름 — 형식은 작업의 `attendees`와 같음
- 홈 위쪽에 **오늘 일정** 한 줄 요약 (자동 녹음이 걸린 일정은 🔴 표시)
- 회의 일정에서 **이 회의 녹음 시작** → 참석자를 녹음 칸에 미리 채우고, 끝난 녹음(작업)을 일정에 연결

### 저장 (PostgreSQL, Alembic 마이그레이션)

`events`

| 열 | 형식 | 설명 |
|---|---|---|
| id | UUID | |
| user_id | FK users, CASCADE | 본인 일정만 보임 (기존 규칙과 같음) |
| title | String(100) | |
| kind | `meeting` / `other` | |
| starts_at, ends_at | timestamptz | 종일이면 날짜 00:00 ~ 다음 날 00:00 |
| all_day | bool | |
| location, memo | String null | |
| attendees | JSONB `[]` | `[{name, role}]` |
| reminders | int[] | 몇 분 전에 알릴지. 예 `{10, 1440}` |
| auto_record | bool | 3번 기능 |
| job_id | FK jobs, SET NULL | 연결된 녹음. 작업을 지워도 일정은 남음 |
| auto_record_state | `none`/`armed`/`started`/`skipped`/`failed` | |
| auto_record_note | String null | 건너뛴·실패한 이유 (화면에 표시) |
| calendar_uid | String null | Mac 캘린더 앱에 만든 일정의 ID (휴대폰 알림용, 아래 2-C) |

`event_reminders_sent` — (event_id, minutes_before) 고유. **한 번 울린 알람은 다시 울리지 않게** 기록

반복 일정(매주 월요일 등)은 1차에서 제외 (2026-10-29 확정).

## 2. 알람

| 방법 | 언제 울리나 | 한계 | 1차 |
|---|---|---|---|
| **A. Mac 알림** | 백엔드가 켜져 있으면 브라우저를 닫아도 | Mac 화면에만 | ✅ (추천) |
| B. 화면 알림 | 말모아 탭이 열려 있을 때 | 탭을 닫으면 안 울림 | ✅ (덤) |
| **C. 휴대폰** — Mac 캘린더 앱 → iCloud → 아이폰 | 아이폰 기본 캘린더가 직접 울림. Mac이 잠자거나 꺼져 있어도 | 일정 제목·시간·장소가 사용자 iCloud에 올라감 | ✅ (2026-10-29 결정) |

- **검사기**: 백엔드가 1분마다 "지금 울려야 할 알람"을 찾음 (`app/services/reminders.py`, FastAPI 시작 때 백그라운드 작업으로 실행)
- **Mac 알림**: `osascript -e 'display notification "…" with title "말모아"'` — 외부 전송 없음. 처음 한 번 macOS가 알림 허용을 물을 수 있음
- **화면 알림**: 프런트가 알람 목록을 폴링해 토스트 + 브라우저 `Notification`(허용한 경우)
- **놓친 알람**: Mac 잠자기·백엔드 꺼짐 동안 지나간 알람은 몰아서 울리지 않음. 다시 켜졌을 때 일정이 아직 시작 전이면 한 번만 "곧 시작" 알림
- 알람 시점 선택지: 정시, 5분, 10분, 30분, 1시간, 하루 전 (여러 개 가능)

### 2-C. 휴대폰 알림: Mac 캘린더 앱으로 내보내기

- 일정을 저장·수정·삭제하면 백엔드가 Mac **캘린더 앱**의 "Malmoa" 캘린더(iCloud 계정 안, 사용자가 2026-10-29 만듦. 이름은 `APPLE_CALENDAR_NAME`)에 같은 일정을 만들고·고치고·지움 (`app/services/apple_calendar.py`, `osascript`로 Calendar 앱 조작)
- **고칠 때는 지우고 새로 만듦**: 이미 있는 일정의 알림은 Calendar 스크립트로 지울 수 없음(`delete … alarm` → -10000 오류, 2026-10-29 확인). 그래서 수정 = 예전 uid 일정 삭제 + 새로 만들기, 새 uid를 `events.calendar_uid`에 저장. 캘린더에 넘기는 값(제목·장소·종일·시작·종료·알림)이 그대로면 다시 만들지 않음 (메모만 고친 경우 등)
- 알림은 `display alarm`(trigger interval = −분)으로 넣음. **종일 일정에는 캘린더 앱의 '종일 이벤트 기본 알림'이 추가로 붙을 수 있고 지울 수 없음** (캘린더 앱 설정에서 바꿈)
- 종일 일정의 끝: 말모아는 '다음 날 0시'로 저장, 캘린더 앱에는 마지막 날을 넘김 (그대로 넘기면 하루가 늘어남)
- 끄면 더 내보내지 않고 이미 넣은 일정은 캘린더 앱에 남음. 말모아에서 일정을 지우면 (꺼져 있어도) 캘린더 앱의 같은 일정도 지움
- 실패 이유 안내: 권한 없음(-1743) → 시스템 설정 › 개인정보 보호 및 보안 › 자동화, 캘린더 없음(-1728), 응답 없음(-1712·시간 초과 30초)
- 알람 시점(`reminders`)은 그 일정의 **알림**으로 넣음 → iCloud가 아이폰에 동기화 → 아이폰 캘린더가 울림
- **한 방향**: 말모아 → 캘린더. 아이폰에서 고친 내용은 말모아로 돌아오지 않음 (화면에 안내)
- 넘기는 것: 제목, 시작·종료, 장소, 알림. **메모·참석자·녹음·원문은 넘기지 않음**
- 설정 화면에 켜기/끄기 (기본 끔). 켤 때 "일정 제목·시간·장소가 iCloud에 저장됩니다" 안내
- 처음 한 번 macOS가 "말모아(터미널/Python)가 캘린더를 제어하려 함" 권한을 물음 → 거부하면 일정은 말모아에만 저장되고 화면에 이유 표시
- 필요 조건: Mac과 아이폰이 같은 Apple 계정, 아이폰 설정 › 캘린더 › iCloud 켬
- 내보내기가 실패해도 말모아 일정 저장은 성공으로 처리하고, 일정 옆에 "아이폰 동기화 실패 · 다시 시도" 표시

## 3. 시간이 되면 자동 녹음

### 가장 중요한 제약: 녹음은 브라우저가 한다

말모아의 녹음은 **브라우저**가 마이크로 받아 IndexedDB에 10초마다 저장하는 구조입니다 (`frontend/src/hooks/useRecorder.ts`).
백엔드는 마이크에 손대지 않습니다. 따라서 자동 녹음은 아래가 **모두** 맞을 때만 됩니다.

1. 말모아 탭이 **열려 있음** (어느 화면이든 앱 안이면 됨 — 녹음 상태는 `recorder-context.tsx`가 화면 이동과 무관하게 유지)
2. 마이크 권한이 **허용**으로 저장돼 있음 (localhost에서 한 번 허용하면 유지. "매번 묻기"면 사용자 클릭 없이 시작 불가)
3. Mac이 **깨어 있음** (잠자기 중에는 아무것도 실행되지 않음)
4. 지금 **다른 녹음 중이 아님**

백엔드로 녹음을 옮기는 방식(ffmpeg로 직접 녹음)은 기존 구조(브라우저 보존·재개, 화면 레벨 표시, 회의실 모드)를 두 갈래로 나누게 되어 1차에서는 하지 않습니다.

### 흐름

| 시각 | 무슨 일이 일어나나 |
|---|---|
| 일정 저장 시 | `auto_record_state = armed`. 첫 사용이면 아래 **안내 문구**에 동의 받음 |
| 시작 10분 전 | (알람 설정 시) 알람. 동시에 **사전 점검** — 탭이 없거나 권한이 없으면 Mac 알림으로 경고 |
| 시작 1분 전 | 탭 안에 배너: "1분 뒤 '주간 회의' 자동 녹음 시작 · **취소**" |
| 시작 시각 | 녹음 시작. 참석자·마이크·회의실 모드는 일정과 설정값으로 채움. Mac 알림 "자동 녹음을 시작했습니다". 탭 제목 앞에 `● 녹음 중` |
| 종료 시각 | **자동으로 멈추지 않음** (1차). 사용자가 **종료**를 누르고 기존처럼 "녹음 완료" 화면에서 서버로 보냄. 만들어진 작업을 `events.job_id`에 연결 |

- **늦은 시작 허용 범위: 시작 시각 + 10분.** 그 안이면 늦게라도 시작하고, 지나면 `skipped`로 남기고 알림. (백그라운드 탭의 타이머 지연, 잠자기에서 깬 직후를 흡수)
- **수동으로 언제든 중지·일시정지 가능** — 자동으로 시작했을 뿐 일반 녹음과 같음

### 구현 메모

- **프런트 스케줄러** (`hooks/useAutoRecord.ts`, 앱 셸에 한 번 마운트)
  - 15초마다 다음 `armed` 일정을 확인. 시각 비교는 `Date.now()` 기준 (Chrome은 숨은 탭의 타이머를 최대 1분 간격으로 늦추므로 짧은 주기 + 허용 범위로 대응)
  - **탭이 여러 개면 한 탭만** 녹음: `navigator.locks.request('malmoa-auto-record', …)` 로 담당 탭 1개 선정
  - 시작은 기존 `useRecorder().start()`를 그대로 호출
  - 레벨 표시용 `AudioContext`는 사용자 동작 없이 만들면 정지 상태일 수 있음 → **녹음(MediaRecorder) 자체는 영향 없음**. 레벨 막대는 탭을 한 번 누르면 살아남. 구현 때 실제로 확인할 것
  - 시작 결과를 서버에 보고: `POST /api/events/{id}/auto-record` `{state, note}`
- **탭 생존 신호**: 프런트가 30초마다 `POST /api/recorder/heartbeat` `{micPermission: "granted"|"prompt"|"denied"}` (`navigator.permissions.query({name: 'microphone'})`)
  - 백엔드 검사기가 자동 녹음 5분 전에 최근 2분 안의 신호가 없으면 Mac 알림 "말모아 탭이 열려 있지 않아 자동 녹음을 할 수 없습니다. http://localhost:3001 을 열어 두세요"
  - 권한이 `granted`가 아니면 "마이크 권한을 '허용'으로 바꿔 주세요"
- **Mac 잠자기는 막지 않음** (2026-10-29 결정, `caffeinate` 사용 안 함). 잠자기 중이면 녹음이 시작되지 않음 → 일정 창의 자동 녹음 옆과 사전 점검 알림에 "Mac이 잠자기 상태면 녹음되지 않습니다" 안내. 깨어난 뒤 허용 범위(10분) 안이면 그때 시작
- **겹치는 일정**: 이미 녹음 중(수동이든 자동이든, **다른 탭 포함**)이면 새로 시작하지 않고 `skipped`("이미 다른 녹음이 진행 중") + 알림. 녹음은 처음 시작한 일정에 연결. 다른 탭의 녹음은 녹음 중인 탭이 잡는 `navigator.locks` 잠금 `malmoa-recording`으로 알아냄
- **보내지 않은 녹음**(녹음 완료 화면에 남은 것)이 있으면 지우지 않고 `skipped`

### 안내 문구 (개인정보·법)

자동 녹음은 사용자가 자리에 없어도 녹음됩니다. 첫 사용 때 아래를 보여 주고 동의를 받습니다.

> 자동 녹음은 정해진 시간에 사용자의 확인 없이 마이크 녹음을 시작합니다. **본인이 참석하는 회의에만** 사용하고, 참석자에게 녹음한다는 사실을 알려 주세요. 본인이 참여하지 않는 대화를 녹음하는 것은 법(통신비밀보호법)에 어긋날 수 있습니다. 녹음 파일은 이 Mac에만 저장되고 외부로 보내지 않습니다.

녹음 중임을 숨기지 않습니다: 화면 배지, 탭 제목 `● 녹음 중`, 시작·종료 Mac 알림.

## API (구현됨 — 자세한 형식은 `04-API명세.md`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/events?from=&to=` | 기간 내 일정 |
| POST | `/api/events` | 일정 추가 |
| PUT | `/api/events/{id}` | 수정 (시각을 바꾸면 보낸 알람 기록 초기화, `auto_record_state`는 다시 `armed`) |
| DELETE | `/api/events/{id}` | 삭제 — 일정과 알람 기록만. **연결된 녹음 작업은 지우지 않음** |
| GET | `/api/events/reminders?since=` | 화면 알림용: since 이후 울린 알람 |
| POST | `/api/events/{id}/auto-record` | 자동 녹음 결과 보고 `{state: started\|skipped\|failed, note}`. 대기(armed) 일정에 한 번만 (그 밖 409) |
| POST | `/api/recorder/heartbeat` | 탭 생존·마이크 권한 신호 `{micPermission}` (서버 메모리에만) |
| POST | `/api/jobs` 의 form `event_id` | 녹음을 일정에 연결 (`events.job_id`). 녹음을 보낼 때 자동으로 붙음 |

오류 형식·인증은 기존 규칙과 같음 (본인 일정만, 없으면 404).

## 시험 계획 (자동 녹음)

headless Chrome + 가짜 마이크, 시험 백엔드(malmoa_test DB)로:
- 1분 뒤 일정 → 시작 시각에 녹음이 시작되는가, 참석자가 채워지는가
- 탭을 **백그라운드**로 둔 채 → 허용 범위 안에 시작되는가
- 탭 **2개** → 녹음이 하나만 생기는가
- 마이크 권한 **거부** → 시작하지 않고 `failed` + 이유가 남는가, 사전 경고가 오는가
- **수동 녹음 중** 일정 도래 → `skipped`
- 탭을 닫은 채 일정 5분 전 → 백엔드가 경고 알림을 보내는가
- 녹음을 끝내고 보내면 작업이 일정에 연결되는가
- 알람이 서버 재시작 뒤 **다시 울리지 않는가**

실제 Mac 알림 표시와 잠자기 동작은 headless로 확인할 수 없으므로 사용자 Mac에서 직접 확인합니다.
