## 1. meerkit은 어떤 패키지인가

| 항목 | 내용 |
|---|---|
| 이름 | `@snackcup/meerkit` (npm 공개, `0.1.0-rc.9`) + 입구 패키지 `create-meerkit` |
| `bin` | `meerkit` — `init`, `setup`, `start`, `stop`, `status`, `add feature`, `update` 등 |
| `exports` | **`./init` 하나뿐** (CLI 내부 함수). React 컴포넌트·인증 함수는 내보내지 않는다 |
| `files` | `bin`, `src`, `template` — `template/`에 Next.js 프론트와 FastAPI 백엔드 전체가 들어 있다 |
| 동작 | `init`이 템플릿을 **빈 폴더에 복사**한다(비어 있지 않으면 거부). 복사한 파일 해시를 `.meerkit/manifest.json`에 남기고, `update`가 그 기록으로 새 버전을 병합한다 |

→ "설치해서 import하는 라이브러리"가 아니라 **코드를 복사해 주는 스타터킷**(shadcn/ui와 같은 방식)이다.

## 2. meerkit이 가진 로그인·인증 기능

복사된 프로젝트(`~/Desktop/malmoa`) 안에서 쓸 수 있는 것.

**프론트** (`frontend/src/meerkit/index.ts`가 묶어 내보냄)

- 로그인 화면: `AuthPanel`, `AuthDialog`(Provider에 포함), `GoogleButton`, `ForgotIdForm`, `UserMenu`, `UserAvatar`, `ProfileImageField`
- 흐름: `MeerkitProvider`(새로고침 때 세션 복원), `RequireAuth`, `RequireRole`, `useAuth`, `useLogout`
- API: `api/client.ts`의 axios `api` — Bearer 헤더 자동, 401이면 refresh 쿠키로 한 번 재시도
- 멤버 관리: `MemberTable`, `MemberDirectory`, `RoleAssignDialog`, `useMembers` 등, `/admin/members` 화면
- 페이지: `/me`, `/reset-password`, `/auth/google/callback`, `/terms`, `/privacy` (`app/(meerkit)/`)
- 설정: `frontend/meerkit.config.ts` (가입 항목, 이메일 인증, 약관, 로그인 잠금, 테마)

**백엔드** (`backend/app/`)

- `auth`: 가입(이메일 인증번호), 로그인, refresh, 로그아웃, 비밀번호 재설정, 연속 실패 잠금
- `social`: 구글 로그인 / `account`: 내 정보·관리자 회원 관리 / `permissions`, `core/principal`: 역할(MASTER) 검사 / `mail`: 메일 발송

**토큰**

- 액세스 토큰: JWT HS256, `sub` = 사용자 id(**정수**), `type=access`, 30분(`JWT_EXPIRE_MINUTES`). 브라우저 **메모리에만** 둔다
- 리프레시 토큰: httpOnly 쿠키 `meerkit_refresh`, 경로 `/api/auth`, SameSite=Lax, 14일
- 프론트는 `/api/*`를 Next.js rewrites로 백엔드(8000)에 넘기는 구조가 전제다 (쿠키를 같은 출처로 유지)
- 액세스 토큰 검사 때 서버는 계정 정지(`is_active`, `deactivated_at`)와 비밀번호 변경 시각(`password_changed_at`)도 확인한다

**없는 것:** 초대, 팀·워크스페이스. 멤버 관리는 "서비스 전체 회원을 관리자가 관리"하는 수준이다.

## 3. 지금 상태로 말모아에서 쓸 수 있나

`npm install` 후 import하는 방식으로는 **쓸 수 없다.**

- npm 패키지에 화면·인증 exports가 없다.
- 백엔드는 파이썬 코드라 npm으로 전달되지 않는다.
- `init`은 빈 폴더 전용이라 기존 말모아에 바로 붙일 수 없다.

## 4. 설치 방식 판단

| 방식 | 판단 |
|---|---|
| npm 설치 (import) | ❌ import할 것이 없다. 하려면 meerkit을 라이브러리로 새로 만들어야 해서 "meerkit 수정 최소"와 맞지 않는다 |
| 로컬 패키지 연결 (`file:`, `npm link`) | ❌ 같은 이유 |
| **코드 복사 + 인증 서버 분리** | ✅ **추천.** meerkit 본래 사용 방식이고 meerkit 코드를 고치지 않는다 |

## 5. 말모아 구조와의 호환성

| 항목 | meerkit | 말모아 | 결과 |
|---|---|---|---|
| 백엔드 | FastAPI, SQLAlchemy, Alembic | 같음 | ✅ |
| `users.id` | **int** | **UUID** (`jobs`, `people`, `events`, `llm_settings`, `llm_usage`, `llm_usage_limits`가 FK) | ❌ 가장 큰 충돌 |
| 표 이름 | `users` | `users` | ❌ 한 DB에 넣으면 충돌 |
| 비밀번호 칸 | `hashed_password` | `password_hash` (자리 표시 값) | ❌ |
| 토큰 전달 | Bearer + refresh 쿠키 | 없음 (`send()`, XHR 업로드에 헤더 없음) | 🔧 추가 |
| API 호출 | axios, 상대 경로 `/api` (프록시) | fetch, 절대 주소 `http://localhost:8010` | ✅ 주소가 달라 함께 쓸 수 있음 |
| DB 포트 | Docker Postgres **5432** | pgserver, 기본 **5432** | ⚠️ 둘 다 켜면 충돌 |
| 서버 포트 | 프론트 3000 / 백엔드 8000 | 3001 / 8010 | ✅ |
| `components/ui` | shadcn 기본 | 98 OS로 고친 shadcn | ❌ 같은 이름에 내용이 다른 파일 11개 (아래) |
| `lib/utils.ts` | 다름 | 다름 | ⚠️ 합쳐야 함 |
| 공통 라이브러리 | react-query, zustand, radix-ui, sonner, Next 16.4.2 | 같음 | ✅ `axios`만 추가 |

`components/ui` 비교 결과

- 이름이 같고 내용이 다름(11): `badge`, `button`, `card`, `checkbox`, `input`, `label`, `separator`, `skeleton`, `sonner`, `table`, `tabs` (그 밖에 `lib/utils.ts`도 다름)
- 말모아에 없음(9, 그대로 추가 가능): `accordion`, `avatar`, `chart`, `dialog`, `dropdown-menu`, `file-dropzone`, `native-select`, `pagination`, `radio-group`

**결론:** DB를 합치지 않는다. meerkit 백엔드를 **인증 서버로 따로 띄우고**, 말모아는 meerkit이 발급한 JWT만 검증한다. meerkit의 정수 id와 말모아의 UUID 사용자는 **연결 칸 하나**로 잇는다.

## 6. 구현 계획 (추천안)

```
브라우저 (말모아 프론트 :3001)
 ├─ /api/auth/*, /api/users/* …  → Next 프록시 → meerkit 백엔드 :8000  (로그인·회원·멤버 관리, DB: meerkit)
 └─ http://localhost:8010/api/jobs … (Bearer)  → 말모아 백엔드 :8010   (JWT 검증만, DB: malmoa)
```

### meerkit 쪽 — 코드 수정 없음

- `~/Desktop/malmoa`를 인증 서버로 그대로 실행한다 (백엔드 8000, Docker DB).
- 설정만 바꾼다: `backend/.env`의 `CORS_ORIGINS`에 `http://localhost:3001` 추가, `FRONTEND_BASE_URL=http://localhost:3001`(메일 링크).
- `JWT_SECRET_KEY`를 말모아와 **같은 값으로** 둔다 (값은 각 `.env`에만, 문서에 쓰지 않는다).
- DB 포트 충돌 해결 (어느 쪽을 옮길지 결정 필요).
- 나중에 다른 서비스도 쓸 공통 기능(예: 초대)은 meerkit 저장소에 **새 모듈로 추가**한다. 기존 파일은 고치지 않는다.

### 말모아 쪽

**백엔드**

1. `pyjwt` 다시 추가. 설정 `JWT_SECRET_KEY` 추가, 비어 있으면 시작하지 않음.
2. 마이그레이션 1개: `users.meerkit_user_id INTEGER UNIQUE NULL`. 기존 UUID·FK는 그대로. 적용 전 `backups/`에 DB 덤프.
3. `core/security.py`의 `get_current_user`: Bearer JWT 검증(`type=access`, 만료) → `sub`로 사용자 찾기, 없으면 만들기(첫 로그인 자동 생성) → 토큰이 없거나 틀리면 401.
4. 로컬 계정 `local@malmoa.local`의 작업·일정·참석자·AI 설정을 누구에게 넘길지 결정 후 구현 (예전 `adopt_local_user`는 커밋 `c62cd15`).
5. 테스트: 토큰 없음 401, 서명 틀림 401, 만료 401, 처음 보는 사용자 자동 생성, 기존 `X-Test-User` 테스트 59개 유지.

**프런트**

1. `src/meerkit/` 폴더를 통째로 복사(손대지 않는 영역), `meerkit.config.ts`, `app/(meerkit)/` 페이지 복사.
2. `components/ui`: 없는 9개는 추가, 겹치는 11개는 **말모아 파일 유지** 후 meerkit 화면에서 깨지는 곳만 확인. 이번 작업에서 가장 손이 많이 갈 곳.
3. `axios` 추가, `next.config.ts`에 `/api/:path*` → `localhost:8000` rewrites (말모아 API는 절대 주소 8010이라 겹치지 않음).
4. `lib/api.ts`의 `send()`·`createJob()`(XHR)에 `useAuthStore`의 토큰을 싣고, 401이면 `refreshAccessToken()`으로 한 번 재시도.
5. `providers.tsx`를 `MeerkitProvider`로 감싸고, `AppShell`에서 로그인 전이면 `AuthPanel` 표시. 메뉴(파일·시작 메뉴)에 로그아웃·내 정보 추가.
6. 1차는 `theme: "shadcn"`으로 두고, 98 OS 스타일 맞추기는 다음 단계.

### 이후 확장

- **멤버 관리:** meerkit `/admin/members`를 그대로 쓴다 (서비스 전체 회원·역할).
- **초대:** meerkit에 없다. "회의록을 함께 보는 팀" 단위라면 말모아 쪽에 `workspaces`, `workspace_members`, `invitations` 표를 새로 만든다. 초대 메일은 meerkit `mail`의 방식을 참고.

### 알아 둘 한계

말모아는 토큰 **서명만** 확인한다. meerkit에서 계정을 정지하거나 비밀번호를 바꿔도 이미 발급된 액세스 토큰은 **최대 30분** 더 통한다. 더 엄격해야 하면 말모아가 meerkit `/api/users/me`로 확인하게 바꿀 수 있지만 요청마다 한 번씩 더 호출한다.

### 쓰지 않은 방법

- 말모아 기능을 meerkit으로 생성한 `~/Desktop/malmoa`로 옮기기 — "통째로 합치지 않음"과 맞지 않음.
- 두 DB를 하나로 합치기 — `users` 표 이름·id 형식 충돌, 말모아 FK 6개를 전부 바꿔야 함.
