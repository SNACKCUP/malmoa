# 03. 구조

> **2026-11-03 통합 단계 1 이후:** 백엔드는 `~/Desktop/malmoa/backend`(meerkit 프로젝트) 안 `app/features/malmoa/`에 있다 (`api/`·`services/`·`schemas/`는 아래 설명과 같고, `core/config.py`→`config.py`, `db/models.py`→`models.py`, `core/storage.py`→`store.py`, `db/session.py`→`db.py`(meerkit 엔진 공유), `core/security.py`→`deps.py`(meerkit 로그인)). ## 데이터 저장 위치

**원칙:** DB에는 상태·메타데이터만, 큰 데이터는 파일.

| 데이터 | 위치 |
|---|---|
| 사용자 | DB `users` (id UUID, email, password_hash, created_at). 지금은 로컬 계정 하나, `password_hash`는 쓰지 않는 자리 표시 값 |
| AI 사용량 | DB `llm_usage` (id, user_id, job_id(작업 삭제 시 NULL), file_name, provider, model, calls, input_tokens, output_tokens, created_at) — AI 호출마다 한 줄. DB `llm_usage_limits` (user_id PK, monthly_tokens, daily_calls, updated_at) |
| AI 회의록 연결 | DB `llm_settings` (user_id PK, provider, model, base_url, api_key_enc(Fernet 암호문), key_hint, updated_at). 없으면 `.env` |
| 참석자 명단 | DB `people` (id, user_id, name, role, created_at, UNIQUE(user_id, name)) |
| 작업 상태 | DB `jobs` (id `moa-<UUID>` 글자 40자(2026-11-02부터, `core/job_id.py`), user_id, file_name, stored_name, source, created_at, updated_at, size_bytes, duration_sec, status, progress, stage, error_message, transcript_ready, minutes_ready, llm_tokens, attendees JSONB `[{name, role}]`) |
| 원본 음성·사진 | `backend/storage/uploads/{job_id}{확장자}` (예: `moa-79f7e21d-….webm`) |
| 변환 원문 | `backend/storage/transcripts/{job_id}.json` (`{jobId, text, segments[]}`), `.txt` |
| 회의록 | `backend/storage/minutes/{job_id}.md`, `{job_id}.json`(메타) |
| 처리 중 임시 | `backend/storage/work/{job_id}/` (audio.wav, plan.json, part_NNN.json), `work/{job_id}_minutes/` |
| DB 데이터 | `backend/storage/postgres/` |
| 예전 JSON 작업 | `backend/storage/jobs/` — 1차 구현 시절 형식. 로컬 계정 생성 시 DB로 이관 |
| 브라우저 녹음 조각 | 사용자 브라우저 IndexedDB (서버 아님) |

JSON 파일은 `write_json_atomic`(임시 파일 → rename)으로 씁니다.

## 처리 흐름

```text
[브라우저 녹음] ─10초 조각→ IndexedDB ─종료→ Blob ─┐
[음성 파일 선택] ──────────────────────────────────┤
[화이트보드 사진] ─────────────────────────────────┘
          │ POST /api/jobs (multipart: file, source)
          ▼
   uploads/ 저장 + jobs 행 생성 (QUEUED)
          │ POST /api/jobs/{id}/transcribe → 202
          ▼
   DB 대기열 (jobs.task) → 작업자가 하나씩 가져감 (SKIP LOCKED, 생존 신호, 끊기면 다시 대기열)
          │
   ┌──────┴────────────┐
 음성                   사진
 ffmpeg→WAV            Apple Vision
 조용한 지점 경계       줄 정렬·확신도
 구간별 Whisper·저장
   └──────┬────────────┘
          ▼
   transcripts/{id}.json·.txt, transcript_ready=true, COMPLETED
          │
   ┌──────┴──────────────────────────────┐
 복사 3종 (API 없이)            POST /minutes → SUMMARIZING
 → ChatGPT·Claude에 붙여넣기     chunker → map(구간 메모) → reduce
                                 minutes/{id}.md, minutes_ready=true, COMPLETED
                                 → 편집(PUT) · MD/TXT 다운로드
```

## 프런트엔드 상태 관리

| 종류 | 도구 | 예 |
|---|---|---|
| 서버 데이터 | TanStack Query | 작업 목록·작업·원문·회의록·health·참석자 명단. 키는 `hooks/queries.ts`의 `keys` |
| 클라이언트 설정 | Zustand + persist | 마이크·회의실 모드(`stores/recorderPrefs.ts`), 녹음 중인 회의의 참석자 초안(`stores/meetingDraft.ts`) |
| 녹음 상태 | React Context | `RecorderProvider`/`useRecorderContext` — 화면 이동해도 유지 |
| 녹음 조각 | IndexedDB | `lib/recordingStore.ts` |

API 주소는 `NEXT_PUBLIC_API_URL`(`.env.local`, 기본값 없음). 모든 요청은 `lib/api.ts`를 거치며 meerkit 액세스 토큰을 Bearer로 싣고(401이면 한 번 갱신), 오류는 `ApiError`(서버의 `detail` 메시지)로 바꿉니다. 브라우저의 `/api/*`는 `next.config.ts` rewrites로 meerkit 백엔드(`MEERKIT_API_URL`)에 넘깁니다. meerkit 화면 코드는 `src/meerkit/`(원본 그대로, 고치지 않음).

## 설정 (`backend/.env`)

|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg://malmoa@localhost:5432/malmoa` | `db.sh init`이 비밀번호 포함해 기록 |

| `WHISPER_LANGUAGE` | `ko` | |
| `SEGMENT_MINUTES` | `5` | 변환 구간 길이 |
| `MINUTES_CHUNK_CHARS` | `12000` | 회의록 구간 글자 수 |
