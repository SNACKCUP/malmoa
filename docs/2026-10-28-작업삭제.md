# 작업 삭제 기능 (2026-10-28)

> 최근작업에서 내용을 삭제 가능하게 해줘

## 삭제 범위 (CLAUDE.md: "원본과 관련 결과물의 삭제 범위를 명확히 한다")

| 지우는 것 | 위치 |
|---|---|
| 원본 음성·사진 | `storage/uploads/{stored_name}` |
| 변환 원문 / 읽은 글 | `storage/transcripts/{id}.*` (.json · .txt, 재변환 때 보관한 이전 결과 포함) |
| 회의록 (고친 내용 포함) | `storage/minutes/{id}.*` (.md · .json) |
| 처리 중 임시 파일 | `storage/work/{id}/`, `storage/work/{id}_minutes/` |
| DB 도입 전 작업 기록 | `storage/jobs_legacy/{id}.json` |
| 작업 기록 | DB `jobs` 행 (상태·참석자 포함) |

| 지우지 않는 것 | 이유 |
|---|---|
| 참석자 명단 (`people`) | 다른 회의에서도 쓰는 공용 명단 |
| 브라우저에 남은 녹음 (IndexedDB) | 서버 데이터가 아님. 서버로 보낸 녹음은 이미 브라우저에서 지워짐 |
| 이미 내려받은 TXT·MD 파일 | 사용자의 다운로드 폴더 |

## 동작

- **처리 중인 작업은 삭제 불가**: 변환·회의록 작성 중이거나 대기열에 있으면 409 "처리 중인 작업은 삭제할 수 없습니다…". 화면에서도 삭제 버튼이 비활성
- **파일 먼저, 기록은 나중**: 파일 삭제가 실패하면 500을 돌려주고 작업 기록은 남겨 다시 시도할 수 있게 함
- 다른 사용자의 작업·잘못된 ID는 404 (기존 규칙과 같음)

## API

`DELETE /api/jobs/{id}` → 204 / 404 / 409 / 500

## 화면

- 홈 **최근 작업**과 **작업 목록**의 각 줄 오른쪽 끝에 🗑 버튼 (`aria-label="{파일명} 삭제"`)
- 누르면 확인 창: 파일명, 지워지는 항목(원본·원문·회의록이 있으면 회의록·작업 기록과 참석자 N명), "되돌릴 수 없습니다", "참석자 명단은 지워지지 않습니다. 필요하면 먼저 TXT·Markdown으로 내려받으세요"
- **삭제** → 목록에서 바로 사라짐. 실패하면 목록 위에 오류 안내
