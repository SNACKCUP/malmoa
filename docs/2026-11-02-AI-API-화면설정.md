## 2. 목표

1. 설정 화면에서 **AI 제공자 → API 키 → 모델**을 고르고 저장하면, 백엔드 재시작 없이 다음 회의록부터 그 설정으로 만든다.
2. 키는 **화면에 다시 보여 주지 않는다** (저장 후에는 `sk-p…AbCd`처럼 앞뒤 몇 글자만).
3. 저장 전에 **비용이 들지 않는 방법으로 키를 확인**하고, 그 키로 쓸 수 있는 모델 목록을 불러와 고르게 한다.
4. `.env` 방식도 계속 동작한다 (화면 설정이 없으면 .env 값을 쓴다).

## 3. 지원할 제공자

| 제공자 | 호출 방법 | 키 확인·모델 목록 (무료) | 비고 |
|---|---|---|---|
| **OpenAI** | `openai` SDK (지금 방식 그대로) | `models.list()` | 기본값 |
| **Anthropic (Claude)** | `anthropic` SDK 새로 추가 → `messages.create` | `models.list()` | OpenAI 호환 주소도 있지만 JSON 응답 형식 지정이 무시되어 회의록 JSON이 깨질 수 있어 전용 SDK 사용 |
| **Google Gemini** | `openai` SDK + Gemini의 OpenAI 호환 주소 | `models.list()` | 별도 라이브러리 없이 처리. JSON 모드 동작은 구현 때 실제로 확인 |
| **OpenAI 호환 (직접 입력)** | `openai` SDK + 사용자가 입력한 주소 | `models.list()` (안 되면 모델 이름 직접 입력) | Ollama 같은 로컬 모델(`http://localhost:11434/v1`, 키 없음)도 여기로. 이때는 텍스트가 외부로 나가지 않음 |

→ 새 라이브러리는 `anthropic`(Claude 호출)과 `cryptography`(키 암호화) 두 개만.

호출 부분은 `_ask()` 하나만 제공자별로 갈라지게 한다 (구간 나누기·요약·통합·재시도·사용량 기록은 그대로). `_friendly()` 오류 안내도 Anthropic 오류 종류를 추가한다.

## 4. 키를 어디에 어떻게 저장하나

**DB 새 표 `llm_settings` (사용자마다 1행)** — Alembic 마이그레이션으로 추가.

| 열 | 내용 |
|---|---|
| `user_id` (PK, FK users) | 사용자별 설정 → 나중에 여러 사람이 써도 각자 자기 키 |
| `provider` | `openai` / `anthropic` / `gemini` / `compatible` |
| `model` | 예: `gpt-5.4-mini` |
| `base_url` | `compatible`일 때만 |
| `api_key_enc` | **암호화한 키** (Fernet). 평문으로 저장하지 않음 |
| `key_hint` | 화면 표시용 앞 4~7자 + 뒤 4자 |
| `updated_at` | |

- 암호화 열쇠: `.env`에 새 값 `SECRET_KEY`(32바이트 무작위)를 두고, 없으면 `scripts/db.sh init`처럼 처음 실행 때 만들어 `.env`에 적는다. DB 파일이나 백업만 새어 나가도 키는 읽히지 않는다. (`.env`까지 새면 읽힌다 — 로컬 개인 서비스 수준의 보호)
- `SECRET_KEY`를 잃거나 바꾸면 저장된 키를 풀 수 없다 → 화면에 "키를 다시 입력해 주세요"로 안내.
- 왜 `.env`에 직접 쓰지 않나: 사용자별로 나눌 수 없고, 웹 화면이 서버 설정 파일을 고치는 건 위험하며, 재시작이 필요하다.

**우선순위**: 화면 설정(DB) → 없으면 `.env`. 화면에서 "설정 지우기"를 하면 다시 .env 값을 쓴다.

## 5. API (전부 로그인 필요, 본인 설정만)

| 메서드·경로 | 하는 일 |
|---|---|
| `GET /api/settings/llm` | 현재 설정: `provider, model, baseUrl, hasKey, keyHint, source("screen"\|"env"\|"none")`. **키 원문은 절대 돌려주지 않음** |
| `PUT /api/settings/llm` | 저장. `apiKey`를 비워 보내면 기존 키 유지(제공자를 바꿀 때는 새 키 필요) |
| `DELETE /api/settings/llm` | 화면 설정 삭제 → .env로 돌아감 |
| `POST /api/settings/llm/check` | 입력한(또는 저장된) 키로 **모델 목록 조회** → `{ok, models[], message}`. 토큰을 쓰지 않으므로 비용 없음. 크레딧 부족은 이 방법으로는 알 수 없음 → 안내 문구로 표시 |

- 키 형식 기본 검사(빈칸·공백·길이), `base_url`은 `http(s)://`만 허용.
- 로그에 키를 남기지 않는다 (요청 본문 로깅 금지, 오류 메시지에서 키 제거).
- `/api/health`는 로그인 없이 열리므로 키 관련 정보는 지금처럼 "설정됨/모델명"만, 그리고 .env 기준 유지. 화면별 상태는 위 GET으로.

## 6. 화면 (설정 창에 Fieldset "AI 회의록 연결" 추가)

```
┌ AI 회의록 연결 ───────────────────────────────────────┐
│ 제공자   [ OpenAI            ▼]                        │
│ API 키   [••••••••••••••••     ] [보기]  저장됨: sk-p…AbCd │
│ 주소     [ http://localhost:11434/v1 ]  (호환 제공자일 때만) │
│ 모델     [ gpt-5.4-mini      ▼]  [키 확인·모델 불러오기]    │
│ ⓘ 회의록을 만들 때 변환된 텍스트가 이 제공자에게 전송됩니다.  │
│   음성 파일은 보내지 않습니다. 비용은 제공자 계정에 청구됩니다. │
│                       [설정 지우기(.env 사용)]  [저장]   │
└──────────────────────────────────────────────────────┘
```

- 키 입력칸은 `type=password`, 자동완성 끔. 입력값은 **Zustand·localStorage에 넣지 않고** 저장 요청에만 쓴다.
- 모델 목록을 불러오기 전에도 모델 이름을 직접 쓸 수 있게 한다 (목록 API가 없는 호환 서버 대비).
- 제공자별 키 발급 페이지 링크, 지금의 ".env 고치기" 안내는 "또는 .env로 설정" 접힌 도움말로 옮긴다.
- 기존 연결 상태 표의 "AI 회의록" 줄은 화면 설정을 반영해 `Claude · claude-…` 식으로 표시.
- CLAUDE.md "동작하지 않는 버튼은 만들지 않는다" — 위 버튼 4개는 모두 실제 API에 연결.

## 7. 회의록 생성 쪽 변경

- `generate_minutes(job_id, …)`가 작업 주인(`job.user_id`)의 설정을 DB에서 읽어 클라이언트를 만든다.
- 회의록 JSON에 이미 기록하는 `model`에 제공자도 함께 기록 (`anthropic/claude-…`).
- 구간 요약 중간 결과(`work/{id}_minutes/`)는 제공자를 바꿔도 이어서 쓴다 (형식이 같으므로).

## 8. 보안·주의

- 키는 브라우저 → 백엔드로 한 번만 전송. 지금은 `localhost` http라 같은 Mac 안에서만 오간다. **외부에 배포할 때는 반드시 HTTPS** (배포 논의는 11/01 대화 참고).
- 커밋 전 비밀 검사(`sk-`, `sk-ant-`, `AIza` 패턴)를 diff에 돌린다.
- 시험은 **유료 호출 없이** 한다: 백엔드 pytest는 SDK를 가짜 객체로 바꿔서, 키 확인은 무료인 모델 목록 조회로만. 실제 회의록 생성 시험은 사용자가 크레딧을 충전한 뒤, 승인을 받고 짧은 녹음 1건으로.

### 설계와 다르게 한 것

- **처음 저장 때 .env 키 옮기기**: 화면 설정이 없는 상태에서 키 칸을 비우고 저장하면, 같은 제공자의 `.env` 키를 암호화해 화면 설정으로 옮긴다. (캡처에서 키 칸에 "저장됨 · 바꿀 때만 입력"이 보이는데 저장하면 "키를 입력해 주세요"가 나와 말과 동작이 어긋났음)
- **상태 배지 "정상" → "설정됨"**: 가짜 키로도 "정상"이 떠서 오해 소지. 키가 맞는지는 "키 확인"으로만 안다.
- **`/api/health`는 .env 기준 그대로**: 로그인 없이 열리는 API라 사용자별 설정을 넣지 않음. 화면은 새 API를 씀.
- Claude 응답 형식: 구조화 출력(`output_config.format`) 대신 지시문 + JSON 꺼내기. 회의록 스키마(기본값 있는 Pydantic)를 그대로 쓰고 제공자 4개를 같은 방식으로 다루려고.
